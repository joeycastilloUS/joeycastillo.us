Look-and-feel system · paired (Opus driver + Fable5 navigator, two blind passes, reconciled) · Argus operator console · day 1 of the rollout

What this is. An instrument panel for one operator running live restaurant cutovers at night, often on a phone in the field. It answers “what’s happening tonight, what’s broken, what do I chase” in about three seconds, then supports slow careful exception reading. It is serious, flat, silent and restrained — and it spends its entire expressive budget on the only two things that can cost a cutover night: severity and trust.

Constraint layer — the contradictions and how they resolved

AxisResolvedWhy (from real use)

Densitydense (two-layer)94 sites, ~4/night. Sparse triage band over a dense reading layer.

Contradiction 1 — dense vs bold. Bold hierarchy normally buys contrast with whitespace; dense denies it. Resolved: two density regimes — a sparse oversized triage band (the “seconds” job) above a dense reading layer (the “careful” job). Hierarchy comes from weight, fill and border — not whitespace. Contradiction 2 — restrained vs loud severity. Resolved by the reserved-hue rule: hue is a reserved word, spent only on state. Top 2 traits: serious + bold. Paradigms: structural (primary) + emotional (severity/trust only) on an abstract base. No representational elements.

1. Intent

A night-shift instrument inside the Argus console. Triage in three seconds, then read carefully. The look-and-feel itself enforces the standing orders: classification is part of the frame (O-6), and the renderer is visually incapable of presenting a machine claim as a verified fact (O-7). It must live inside the host console’s surfaces and never let the console’s accent blue mean “state.”

2. System rules

Spacing. 4px base; 4/8/12/16/24/32. Reading layer tight (8px gaps, 12px card padding); triage band and section breaks get 24. Hard floor that overrides density: any tappable element ≥44px — field use is one-thumb use.

Typography. Host sans for prose; monospace for every data atom (site codes, dates, versions, exception IDs) — mono is the trust channel’s typography: it says recorded value, not sentence. Scale 12/13/15/20/28. Weight carries hierarchy: 400 prose, 700 labels, 800 numerics + severity. Legibility floor: nothing carrying meaning below 12px.

Color — hue is a reserved word. Neutrals ~92% of surface. red = confirmed blocker/fact · amber = claimed / open / owed an answer · green = operator-verified ONLY — green is earned; the machine can never mint it · blue = navigation/identity, never state. Classification red is its own darker family so a blocker and the privacy mark don’t read alike. Contrast targets ~7:1 on severity text — night phone screens crush the red/amber distinction, which is exactly why colour is never the only channel.

Density. Triage band ≤7 stats, numbers at 28px/800 — the largest things on screen (an instrument shows its critical gauge biggest). Reading layer ~10–12 rows per viewport. No horizontal scrolling, ever.

Depth. Flat — surface step + 1px border, no shadows. One depth-like device is load-bearing: the left severity rail (4px solid = confirmed, dashed = candidate) — an index you can thumb-scroll, not decoration.

3. Component behavior

Buttons. Rare — this is a read-and-disposition instrument. Disposition controls are the only green-capable controls in the system: green enters the UI exclusively through an operator tap. No red buttons — red is a fact colour, not an action colour. ≥44px on touch.

Cards. Host surfaces, 1px border, 12px padding, left rail encodes severity+trust. Header: mono site code, name, chips; dates in mono ≥12px (they are decision data at night, not footnotes). Trust is a card-level treatment: candidates get a dashed border and hollow chips; confirmed are solid.

Tables. None on phone — stacked cards. Desktop: 44px rows, sticky mono header, no zebra (rails/chips already segment), sorted severity-then-time so position itself encodes priority.

Navigation. Lives in the host sidebar — the app must not grow its own nav. Tabs carry count badges (exceptions red, unanswered questions amber) so triage starts before a pane is opened.

4. Interaction

Transitions. 100–150ms, opacity/background only, ease-out. Nothing translates, scales or slides. No pulsing.

Feedback. Hover = one surface step. Focus = 2px high-contrast ring. Errors inline and fail-closed. Staleness is a first-class state: the snapshot age is quiet while fresh and turns amber when stale — the “re-read before acting” warning becomes a state rather than a permanent sentence the eye has stopped seeing.

The trust grammar (O-7) — the most important thing on the screen

Trust is a fill-state grammar, orthogonal to severity, carried on redundant channels so it survives greyscale, night-shift and fatigue:
StateLooks likeRule
claimed doneHollow — dashed rail, outline chip, lowercaseMachine-derived. Unproven. Never green.
■ EXC-001Solid — solid rail, filled chip, mono ID, capsRecorded fact. The ID is the confirmation artifact; candidates never get one.
✓ verifiedSolid + green + check + who/whenStructurally reachable only from an operator disposition. No code path maps feed data to this class.
Even with all colour removed, hollow-vs-solid + lowercase-vs-caps + no-ID-vs-ID preserves the distinction.

Five independent channels (rail, glyph, label, fill, sort position). A colour-blind operator on a night-shifted phone still triages by rail presence and sort order alone.

INTERNAL ONLY (O-6) without becoming wallpaper

The marking lives in the frame, and gets loud at egress: (1) a sticky classification strip that never scrolls away; (2) stamped into the provenance line so classification travels with data lineage; (3) re-asserted at full size at every egress affordance — share, copy-link, print, export. Banner blindness is beaten not by shouting but by reappearing at the moment content might leave the engagement. (4) The shipped fail-closed check — an unmarked feed refuses to render — is the fourth leg.

The open questions — rendered as debts, not notes

The operator asked for these to be in the design. They are, and the design gives them teeth:
  • UNANSWERED is the loudest element on the card — amber, caps, filled. The question is the body; the debt is the headline.
  • Two debt states, visually distinct. Not yet asked = the operator’s debt (renders an ASK → affordance). Asked, awaiting = the counterparty’s debt (“waiting on Elbert · asked <date>”), with the addressee styled as a to-field — a named person who owes a reply. All 10 currently sit at not-yet-asked, so the tab should read as “you have 10 asks to send.”
  • Priority uses the severity grammar. Q-001 is BLOCKER-FOR-ACCURACY → solid red rail, sorted first — it poisons the default state of every DONE item in the feed. It must not share a chip style with MEDIUM.
  • Q-001 escalates into the triage band as a stat: “1 question blocking accuracy”. A blocker-for-accuracy is a tonight problem, not a tab-three problem.
The 10 live questions: Q-001 does “DONE” mean verified or claimed (blocker) · Q-002 Porter Ranch ingest-device conflict (note says delivered, sheet says FALSE) · Q-003 is the playbook pipeline 1-week-ahead by design or stalled · Q-004 does “no notes” mean nothing-to-report or not-reviewed · Q-005 correct the CA.0032 deck or record as-built · Q-006 who confirms go-live · Q-007 light the Slack channel now or after approval · Q-008 Airtable base + write access (blocker for O-10) · Q-009 manual or automated Airtable writes · Q-010 does an approved+resolved deviation count as “Issues”.

Shipped-code violations this ~laf caught (fixed same session)

1. O-7 violation — a machine claim was rendering GREEN. .k2tag.ok applied via it.done_claimed painted an ingested claim of “done” in solid green — exactly what O-7 forbids the visual layer to do, and doubly wrong while Q-001 (what does DONE mean?) is unanswered. Fixed: claims render hollow amber; green is now structurally unreachable from feed data.
2. Candidates were a recoloured clone of confirmed (hue-only difference = colour-alone encoding). Now the hollow grammar.
3. Sub-floor type carrying meaning — severity/trust/date/provenance at 9.5–11.5px. Raised to the 12px floor.
4. Inverted triage hierarchy — the “answer in seconds” numbers were 13px, among the smallest in the console. Now 28px/800.
5. Classification scrolled away on a 94-site list. Now sticky.
6. “unanswered” rendered in link-blue — a blocker question reading as a calm link. Now an amber UNANSWERED badge.
7. Playbook link was a 12px inline link — the single most-tapped thing on an install night. Now a 44px target.

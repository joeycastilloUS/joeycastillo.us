Install Night 6 — record of events

Kitchen Display System (KDS) installation, 2026-08-10 into 2026-08-11.
Harbor & Adams (CA.0077) · Scottsdale (AZ.0106) · Redmond (WA.0089) · Concord (CA.0083). Crews from c1 Techs; oversight by Mendocino Farms. All times US Pacific.

All four stores completed the full cycle and released their technicians. Every site started at 8:30 PM against a shared 10:30 PM smoke-test target. Completions: Scottsdale 12:31 AM, Harbor & Adams 1:26 AM (work finished 12:54 AM, released 1:03 AM), Redmond 2:13 AM, Concord 2:21 AM. All systems fully operational at 2:09 AM.

Concord was the surprise winner. It finished last on the clock (2:21 AM) — but it lost over an hour getting into the restaurant (staff still operating; not the crew’s doing) and was the only site to work through a network cut-over fault. Credit the access delay back and Concord’s three techs normalize to a ~1:15 AM effective finish — in line with the real pace of the night. The operator called it live at 1:18 AM: “Concord had a lot of waste with the network issue but still seem to be tracking.. so Concord would likely be done already.” The analytic point stands on its own: measure effective install time from real site access, not wall-clock, so crews are compared on a level field.

The Concord network fault never reached restaurant operations. After the cut-over the POS came back offline; the smoke test caught it before the site could check out (“smoke test produced smoke”). The operator corrected the network, the site re-tested, and Concord’s smoke test passed at 12:26 AM (“we are good, networks are correct”). The safety check worked exactly as designed.

Root cause and remediation — Concord network

Cut-over configuration fault; corrected and re-verified end to endRESOLVED 00:26EXC-600
  • Fault. After the 10:29 PM network cut-over to the Konducter configuration, the Concord POS came back without network connectivity. The fault was introduced by the cut-over itself; it was not present before the flip.
  • Detection. The smoke-test gate caught it. Concord could not pass its Definition of Done (send an order, see it on a station), so the site could not proceed to checkout. This is the designed function of the gate: the fault surfaced during the install window, under the install team’s control, not in service.
  • Remediation, in order: (1) operator corrected the network configuration on his end (11:23–11:45 PM); (2) site devices were rebooted to obtain new DHCP leases on the corrected network (11:59 PM, 12:18–12:21 AM), with the operator monitoring; (3) the smoke test was re-run at the salad station and passed at 12:24 AM; networks confirmed correct at 12:26 AM.
  • Verification. The clear was proven by the same end-to-end test that caught the fault — an order through Toast appearing on a Konducter station — not by a network reading alone.
  • Scope of the record. The session log records the fault, the correction sequence, and the verified clear. It does not name the specific configuration element that was wrong; that detail was worked on the operator’s side and is not in the log.
  • Process note. The prior night’s incident (Night 5, Gainey Ranch) arose from a smoke test that was released but not executed. This night, the same class of fault — a post-flip network problem — was caught by an executed smoke test and cleared before checkout. The process change held.
Evidence — operator “CONCORD - will need them to re-boot to get new leases on the network… I’m monitoring on this end.” (12:21 AM)

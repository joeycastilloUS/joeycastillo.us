Install Night Operating Model

A scheduled, gated install night. Proposed for the remaining stores.

Every time in this model is anchored to arrival on site. Arrival is already established per store. A crew arriving fifteen minutes late pushes every gate that follows by fifteen minutes.

The night runs to a schedule with named gates. Each station is confirmed done as it is completed, not at the end. Re-work is immediate.

Mendocino Farms holds the schedule.

Scheduled gates

Each gate is a clock time, set per store from the arrival time. A gate is either met or it is not; a missed gate is raised at the time, not at checkout.

Early smoke test

Prove the path before the build is finished
  • Ingest and two stations online and testable.
  • Ring a simple order through that executes one use case end to end — till to kitchen screen.
  • Run early enough that a failure still has the night in front of it, not the last hour.

Installation plan — per store, before the night

What the plan contains
  • Start time.
  • Order of events — each station with a start time and a done-by time.
  • Tech assignments — which technicians are working which stations.
  • Planned time allotment per station, with padding built in and a contingency for each.

Ingest — prerequisites before the night

Completed in advance, not on the night
  • Firewall disabled.
  • CrowdStrike installed.

Definition of Done

Applied to each station as it is completed. All four must hold. Anything short is re-work, and re-work happens immediately.

A station is done when
  • It is installed to spec — the playbook.
  • The device survives a reboot.
  • The device is live and reporting green — Meraki and Konductor.
  • The installation photos are approved by Mendocino Farms.

What is needed to make this work

1 · A single technical support line
  • C1 technicians call into the support bridge for technical help during the install.
  • Transcriptions supplied to C1 administrators — no objection to that, it removes friction and streamlines communication.
2 · Playbook-to-reality agreement, established ahead of the night
  • Walk the store against the playbook with C1 before install night and agree what is actually there.
  • If it cannot be done ahead, it is scheduled into the installation plan as its own block of time — not discovered mid-build.
3 · Scheduled confirmation from Mendocino Farms
  • Each station is confirmed on a schedule, as it completes.
  • The point is to avoid queues and pile-ups at the end of the night, when nothing can be fixed without a return visit.
4 · Trello data via API from C1
  • Photos and information provided through the API so they can be ingested and reviewed as they happen, not at the end.
  • Trello holds a very large amount of data and is not usable in its current form — it is being treated as a data repository rather than a working surface.
Gate — a scheduled checkpoint with a clock time and an owner.
Anchor — arrival on site. All gate times are offsets from it.
Smoke test — a minimal end-to-end run proving the path works before the build is complete.
Re-work — correction of a station that does not meet the Definition of Done, carried out immediately.

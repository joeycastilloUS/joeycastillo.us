Ingest says Offline but it’s working

Two minutes. You need a laptop on the store network (same LAN as the POS switch).

What we already know — don’t re-check these:
  • The Ingest device is online. Meraki sees it right now on switch port 23, VLAN 90.
  • It’s the same VLAN as Bread/Salad/Expo, which all report fine.
  • It is not a firewall problem. This traffic never leaves the switch.
  • Ingest has never reported a software version — the other devices all do.
So: don’t swap cables, don’t reboot the switch, don’t touch firewall settings. We’re testing one thing: is the Ingest device answering on port 22288?

The test

1Plug into the POS switch with a network cable.
Wi-Fi will NOT work for this test. No store Wi-Fi puts you on the Ingest’s network — Mendocino Store, mendo001 and Guest all land somewhere else. On Wi-Fi this test fails even when the device is perfectly fine.
Prove you’re on the right network before anything else:
ipconfig
Mac: ifconfig | grep "inet "
Your IPv4 starts with 10.90.100. → correct network. Continue.
Anything else (192.168.1.x, 10.100.9.x, or a random 10.x) → STOP. You’re on the wrong network and every result below will be a false failure. Find the POS switch and plug into it.
2Quick look (optional). Ping can be switched off on the device itself, so a failure here does NOT mean it’s broken — do not stop on this one.
ping 10.90.100.101
Replies come back → device is reachable. Go to step 3.
No reply → keep going anyway. Many devices ignore ping by design. Step 3 is the real test — only trust that one.
3THE ACTUAL TEST — is port 22288 answering?
Windows / PowerShell:
Test-NetConnection 10.90.100.101 -Port 22288
Mac / Linux:
nc -vz -w 5 10.90.100.101 22288

What the answer means

TcpTestSucceeded : True  (or “succeeded!” on Mac) The device is answering on 22288. The network and the device are fine — the problem is on the Konductor side (it’s polling the wrong address, or this store was never added to monitoring).
→ Report: “22288 OPEN, still shows Offline.” Nothing more to do on site.
TcpTestSucceeded : False  (or “Connection refused / timed out”) The device is on the network but nothing is listening on 22288. The Ingest software isn’t running, didn’t finish setup, or a firewall on the Ingest box itself is blocking it.
Then do this, in order:
  • Is the Ingest device powered on and booted? (It has its own power supply — it is not PoE, so a dead switch port won’t show it.)
  • Reboot the Ingest device and wait 3 minutes. Re-run step 3.
  • Still False → Report: “22288 CLOSED after reboot.” The unit needs re-provisioning — that’s not a field fix.

Heads up

  • Wired only. This test only works plugged into the POS switch. Wi-Fi puts you on a different network and everything will look broken.
  • Same test, same address at every store. The Ingest is 10.90.100.101 on port 23 at Broadway, Porter Ranch, Culver City and Sacramento — they are configured identically.
  • Don’t change firewall or VLAN settings. Those come from a shared config template — a change at one store silently breaks the pattern for all 15.
  • If you get the same answer at two stores, say so. That makes it a rollout-wide fix, not a per-store one.

Quadrant reacts when the cron pass finishes

Event-driven, not a timer. The board holds still and only re-pulls a quadrant when the server signals a warm pass completed — one coordinated update per cron finish, every read a cache hit. This is the opposite of the "crazy" refresh we removed (blind per-quad timers racing the server).

Already true confirmed by ~i

  • Client auto-refresh is OFF — pollWarmStatus=0, auto tickClock=0, bgRefresh=0. Only the clock display + manual ↻ remain. Same code for the bare board and the ?k= share link.
  • 4 GCP crons fire on :00 / :15 / :30 / :45 (refresh-active?after=0/15/30/45).
  • The server already stamps the signal — the bridge bumps warmEpoch when a pass completes and exposes /meraki/warm-status {epoch, lastPassMs, lastPassAt}. Nothing to build server-side.

Guardrails & the one caveat

  • Only on advance. No epoch change = the board does nothing. No blind timers, no racing — the exact failure mode we removed.
  • Manual ↻ untouched. Still forces a live read anytime; login gate untouched; share link untouched.
  • Cadence = pass duration. The epoch advances when a pass finishes. ~i measured lastPassMs ≈ 41s with 8 active sites (5 req/s governor). So quads react every ~15–40s depending on how many sites are active — not faster than the server can actually read. If you want a hard 15s reaction with many sites, that's a separate lever (raise the rate cap / shard the pass) — flag it and we decide.
  • Scope of the build: ONE function on the board (poll warm-status + sweep-on-advance) + its boot hook. Server already done. ~15 lines. Opus checks.

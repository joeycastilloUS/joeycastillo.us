Design — pi_run runs the dianoia

Make pi_run load, verify, and execute the dianoetic files — the .pi/.si/.sm triple — for mendo-nps-detractor-triage. The "make it work" step. Minimal delta on the existing pirun engine, not a rewrite.

1. Need

The dianoia is authored and sitting unexecuted at C:\argus\be\pi\dianoia\: the .pi (14 demand clauses + 5 words blocks + config), the .si (14 units, each citing its D#, its micro-op bind, its words, its policy), and nous.sm (the skills catalog). Nothing reads them. Today's runtime (pirun_run.c) executes the old flat card and still hardcodes what the dianoia declares: the panel question lives in a C string, the fold lives in the gcp-bridge (the cleanSafe != 2 roster-coupling bug class — remove a model, the fold silently breaks), the requester/tag/priority live in the jacket, and verify_card checks only (skill,slot,keys) against a sidecar manifest — no demand coverage, no words integrity, no key-flow closure. Until pi_run runs the triple, the words jc owns aren't the words the system speaks, and biRT is a doc claim, not a load-time refusal.

2. Raw User Stories

  • As the operator, I want to change a words block in the .pi and have the next run speak exactly those bytes, so that the intent file is the product — no recompile, no jacket edit.
  • As the substrate, I want to refuse to load on ANY drift between .si↔.pi or .si↔.sm, so that a stale plan can never run against a changed demand.
  • As pi_run, I want to fold the panel's raw verdicts myself with the fold the .si names, so that no jacket ever decides safety and roster changes can't break the fold.
  • As an auditor, I want every executed unit's trace to carry its why: D#, so the ledger shows which demand each action served.
  • As the team, I want the working card at be/pi/mendo-nps-detractor-triage.pi untouched until the dianoetic path is proven, so the live sandbox lane never goes dark.

5. Shape

Minimum viable structure — the pi_run delta, six parts:

a. Loader — .si plan → the existing PiUnit walk

The .si replaces the old protocol: parse. Field mapping:

.si fieldLands inStatus
unit / skill / slot / gate / failPiUnit as-is (parser splits the one-line gate: x  fail: y form)exists
in: / out: (typed, e.g. alert.nps:int)in_keys/out_keys + new per-key type tag. Types are verify-time contracts; ledger values stay strings at runtime.exists + type tag new
why: (D# list)new PiUnit.why[] — verified against .pi, echoed in every trace eventnew
bind: (micro-op)new PiUnit.bind — verified against the .sm; dispatch resolves on it (replaces the (skill,slot) MapRow resolve)new
words: (names)new PiUnit.words[] — names resolved to sealed .pi blocks at loadnew
set: (policy pairs)new PiUnit.set[] — e.g. panel.models, panel.fold, escalation.tag/priority; injected into the callnew
res: (data slots)new PiUnit.res[] — per-env data files (recipients, vault, maps); the existing slots/ mechanism, now declareddeclared (mechanism exists)
idem:new PiUnit.idem template; idem_expand → the jacket's draft_idgeneralizes existing

The .pi side parses card/owner/env, the demand clause IDs (D1..D14), the words <name>: pipe-blocks byte-exact, and config: pairs. The .sm parses to a catalog: {micro_op, in-sig, out-sig, vis, c-symbol}.

b. Verify chain — dia_verify, all before any unit runs

  • .si↔.sm — every bind exists in the catalog, is pub (a priv bind refuses), in-arity matches the in-sig, typed keys agree positionally, every out: key covered by the out-sig (supports alert.* prefix wildcard and bare *).
  • biRT .si↔.pi — every why: D# names a real clause; every referenced words block exists and its hash matches the seal; coverage BOTH ways: every demand clause claimed by ≥1 unit AND every unit claims ≥1 clause. An unclaimed demand or an unjustified unit refuses the load.
  • Key-flow closure — walk units in order accumulating outs; every in: key must be a prior out: or a trigger input (ticket, seeded by pirun_start). A dangling read refuses the load.

Any failure prints the exact drift (unit, field, expected/found) and exits — same posture as today's verify_card REJECT, wider net.

c. Words — sealed at load, spoken exactly

The loader extracts each pipe-block byte-exact, hashes it, writes ledger triples (words:<name>, template, bytes) + (words:<name>, hash, h), and records first-load hashes in <card>.pi.seal (committed; a later load whose hash differs from the seal is drift — reseal is an explicit operator act, re-commit the seal). Dispatch hands the exact bytes to the unit's call: panel-question goes to the panel jacket as the question; escalation-note/subject render via translate_strings with ledger vars ({nps},{store},{feedback}…) — replacing the hardcoded C strings and, for zora blocks, the slots/*.txt copies. The jacket receives text; it never owns it.

d. The fold in C — pantheon_fold

The key move. The panel jacket returns RAW per-model verdicts (illness.verdicts: model + verbatim reply line + ok/err). pi_run then runs the fold the .si names (set: panel.fold = unanimous-safe): safe ONLY if every model in set: panel.models returned a clean SAFE; any ILLNESS, any error, any silence, any missing model → detected. Writes illness.detected/confidence/reason. Roster comes from the .si, the fold counts against that roster — the bridge's cleanSafe != 2 roster-coupling bug class dies because no jacket folds anymore.

e. Jackets → pass-through downstream consequence, not this build

What the bridges STOP deciding and START receiving: gcp-bridge illness-panel lane — stops folding, accepts {input, words, models[]}, returns raw verdicts + cost; zendesk-bridge internal-alert — stops composing, accepts {note, subject, tag, priority, recipients} built by pi_run from words+set+res; recovery/alert lanes — accept requester from config: alert.requester (D13). During cutover the panel lane dual-emits (raw + folded); pi_run prefers raw when present, so neither side ever has a fold gap.

f. config: + migration-safe load path

config: pairs land as (config:<key>, value) ledger triples; dispatch includes them in the jacket payloads. Load-path: the host checks for a sibling <base>.si next to the given .pi — present → dianoetic path (dia_load + dia_verify); absent → today's legacy path, byte-for-byte unchanged. The working card at be/pi/mendo-nps-detractor-triage.pi has no .si sibling and the dianoia/ folder isolates the triple, so the live lane keeps running with zero flags until the dianoetic path is proven.

6. First Move

One commit: dianoia.c (dia_load + dia_verify + words seal) wired into pirun_run behind .si-sibling detection, run against a sandbox ticket: pirun_run C:\argus\be\pi\dianoia\mendo-nps-detractor-triage.pi 457662. Proof = three visible facts: (1) the triple load-verifies clean (all 14 binds pub + matched, all 14 demands covered, key-flow closed) and a deliberately broken why: D99 refuses to load; (2) the ILLNESS LANE runs end-to-end off the dianoia — scan → gate → reduce → panel (question = the sealed panel-question bytes from the .pi) → escalate with the note rendered from the sealed escalation-note/subject blocks → exit; (3) every trace event carries its why: D#. Fold-in-C rides the existing folded jacket response this commit; commit 2 = pantheon_fold + bridge dual-emit.

Into the plan (~p~e sizes these): commit 2 (pantheon_fold + raw verdicts + dual-emit cutover); jacket pass-through fields (note/subject/tag/priority/recipients/requester); recovery lane off the dianoia; typed-key verify tightening; seal-file operator workflow; retire the legacy .pi.skills manifest once the dianoetic path owns the card.

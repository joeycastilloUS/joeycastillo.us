The stale Cloud Build trigger on acmedevUS/meraki-bridge is never exercised. Deploy risk collapses to "did Pages build." Time to live: one push.
  1. Port the prototype. Its <script> block — render(), card(), strip(), the ATT map, filter and accept handlers — plus the #screen-scoped CSS, moved into the shipped tab machinery: APPS.meraki.tabs, the sidebar TABS entry, the dispatch case, ALL_PANES, viewName(), the T map, the 3-segment deep link.   2. Attribution at render. Fetch changes (30d) + apiRequests once on tab open. Join at ±60s by admin. UserAgent meraki-bridge/0 (acmedev) (Meraki.cs:31) → ARGUS (solid, provably us). Any other matching request → API (solid; show admin, sourceIp, UA). No matching request → DASHBOARD (dashed, inferred by absence). Older than the 31-day API window → UNKNOWN, "window expired." The solid-vs-dashed law survives intact.
  3. Accept means "reviewed," not "re-baselined." With no baseline there is nothing to re-bless. localStorage set, keyed by a deterministic fingerprint of the change row. Two-step arm→confirm kept exactly as approved; only the hint copy changes. Precedent already shipped in this repo: Case Patterns judgements are "rev 1, browser-local."
  4. Honesty rails carry the blind spot — see below.

Unknowns

  1. Serialized shape of oldValue/newValue for structured settings (L3 rules, allowed-VLAN lists). If JSON, the set-diff and ordered-move renderers work; if prose strings, we fall back to a plain was→now. Honest either way. One real fetch answers it.
  2. How template pushes appear in the feed — one template row, N network rows, or nothing. Determines how often fan-out grouping fires. The heuristic is safe under all three.
  3. Clock agreement between the two logs. ±60s is a guess — a constant to tune, not an architecture risk, since DASHBOARD is already dashed and inferred.
  4. Real 30-day change volume against the 1000-row single-page cap. Almost certainly fine at five networks; the truncation notice covers the tail.

What we give up — and how the UI admits it

  • EXTERNAL disappears as a badge. A feed-only view cannot show a change the feed never recorded — the amber EXTERNAL card in the prototype was produced by the snapshot backstop, which does not exist in v1. Keeping the badge without the detector would be exactly the dishonesty the ~laf forbade. v1 ships four categories: ARGUS · API · DASHBOARD · UNKNOWN.
  • Presence drift stays invisible — a device added or removed never appears in the feed.
  • Attribution is render-time, not immutable. A change attributed correctly today rolls to UNKNOWN once the 31-day API window passes it — and the card explains that at the moment it happens.
  • Accept is per-browser. The accepted chip says "reviewed on this browser."
The admission, in the lead and the empty state: "Sourced from Meraki's change feed, which misses roughly 20-25% of changes and never records device add/remove. What you see is what Meraki recorded — not a guarantee of everything that happened."

And the empty state reads "No recorded changes," never "No drift."

Traps

  1. The apiRequests 1000-row cap silently poisons DASHBOARD. DASHBOARD is inferred from the absence of a matching request — but if the request log was truncated, absence means nothing. This is the one trap that produces confidently wrong answers. The degrade rule — truncated ⇒ absence verdicts become UNKNOWN "log truncated" — is baked into the join item, not left as polish. Navigator's catch.
  2. Feed rows have no id. Accept keys on a content fingerprint; built sloppily (index, truncated ts) accepted items silently un-accept on the next fetch. Navigator's catch.
  3. Same-admin-same-minute ambiguity. An admin running a script while clicking the dashboard can be mis-joined. The fix is transparency, not cleverness: the Why panel shows the matched request verbatim so you can overrule the machine with your own eyes.
  4. The mockup's sweep vocabulary leaks a machine that doesn't exist — "re-baselines," "backstop sweep," "next sweep in 12 minutes." Every string gets audited during the port; the honesty-rails item owns it. Navigator's catch.
  5. /meraki/changes changes response shape when q is set — {count, changes} wrapped vs a raw array (Program.cs:445-456). Handle both, or never pass q. Navigator's catch.
  6. Scope creep back into the bridge ("just one small cached endpoint…") re-arms the stale-trigger landmine this whole path exists to avoid. Constraint #1 is the tripwire.

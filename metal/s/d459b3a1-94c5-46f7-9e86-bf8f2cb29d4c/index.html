1 · The questions — decide these together · each has its own comment thread below it

Q1 · Trigger source for SCAN

Poll the alert view on a cadence, or a Zendesk webhook on the detractor trigger? Webhook is instant + $0 idle; polling is simpler. Which for v1?

Q2 · How much does reason() decide vs the gate?

v1 = draft-and-hold (you approve every one). When do we let it auto-fire in sandbox with no gate — after N clean approvals? A confidence score from understand()?

Q3 · Code amount policy ($10 vs $20)

Reason() picks by what — severity (nps 0 vs 6)? store? Or always $20 in v1? The macro has both "One Code" and "Two Codes" variants.

Q4 · restate() dialect fidelity

Tyler's replies vary the empathy per complaint. Do we lock a small dialect set (app / pickup / value / service), or let restate() compose freely from the operators each time?

Q5 · v3 corpus flavor

When do we turn on precedent-match (deatomizer + history) so REACT drafts from the closest past reply instead of the template? Not now — but what's the trigger to build it?

Q6 · Cost reporting surface

Where do we show the $0.00-per-react receipt — a line on each drafted reply, a running Argus meter, or in the audit only?

Cost

Inference runs on understand → reason → restate — pure-C99 deterministic operators. No model, no tokens, no GPU. $0.00 per react, replayable, LLM-free. This is the Purcius thesis: Zero-Cost Intelligence, deterministic from the start. (An LLM doing the same react is tokens × price per ticket, forever.)

Hard rules (locked)

  • Sandbox only for real execution; prod stays disarmed — jc fires prod.
  • Food-illness → escalate-only. Never a code, never an auto-reply. Detection + escalation.
  • Operator gate on every send: preview → approve → fire. Idempotent on draft_id; capture-before; audited.
  • Never invent a code — claim from the vault; vault empty → halt.

What shipped

Expanded — 188px. Unchanged from before this work; verified pixel-identical against its baseline.
Collapsed — 56px. The port grid takes the 132px back. Every icon carries a tooltip derived from its own label.
Collapsed, app switcher open. The flyout escapes the narrow rail and opens over the content at full width, names intact. Both of the defects below lived in this one view.

The mechanism

One variable, three consumers. 188px was hardcoded in three places — #tabnav's width, .wrap's margin and its max-width calc (as 220 = 188+32), and #brand-strip's margin. All three now read --navw; body.navcol sets it to 56px. De-duplicating the width and building the collapse are the same change, which is what made this cheap rather than risky.
The mobile query hardcoded margin-left:132px!important — that !important would have silently defeated collapse at ≤640px, so it was rewritten to set --navw instead. Print rules still win, being !important against non-important variable values.
State never lives in the DOM. #tabnav.innerHTML is rebuilt on every render() — tab switch, app switch, data refresh — so anything stored in the toggle button dies on the next click. The truth is a JS variable plus a class on <body>, re-asserted at startup, inside the render, and in the handler, and persisted to argus_navcol.
Tooltips are derived, not written. After the sidebar HTML is assigned, each tab's title is read off its own label. Twenty-five hand-written tooltips would have started drifting the first time someone renamed a tab; these cannot, because the tooltip is the label.

Three defects, caught before shipping

Two of the three were errors in the design, not the build. That is the finding worth keeping from this chain. Fable implemented the locked design faithfully both times and reported the hole rather than quietly patching around it — which is exactly what the driver is supposed to do, and is the only reason they surfaced before the operator saw them.

1 — The flyout could not escape the rail (spec error)

The design said the menu needed only right:auto;width:230px when collapsed. Wrong: #tabnav is overflow:auto, and an absolutely-positioned child cannot escape an ancestor scroll container however it is sized. It rendered as a ~40px sliver with a horizontal scrollbar in the rail. Fixed with position:fixed;left:calc(var(--navw) + 6px), and top measured from the button's getBoundingClientRect() at render time — the first proposal used a hardcoded top:92px, which would rot the moment the toggle's height or the rail padding changed.

2 — Fixing the menu's geometry emptied its contents (spec error)

The design said “hide .appsw-tx” without saying which one. That class sits on the collapsed switcher button (correct to hide) and on every row inside the flyout (wrong). Implemented literally, it produced a 230px panel of four indistinguishable icons. Scoped to .appsw-btn .appsw-tx. Every other class targeted under body.navcol was then audited individually against the flyout markup — .tl, .appsw-cv, .tabv and .appsw-btn are each single-context and safe unscoped; .appsw-tx was the only ambiguous one.

3 — Both were invisible in code review

Neither defect is visible in a diff. Both were obvious within a second of looking at a rendered screenshot. For a change whose entire purpose is visual, reading the code is not verification.

Retro — ~R

What went well

  • Parameterising the width was the whole feature. Because collapse and de-duplication were the same change, three hardcoded copies of 188px became one variable as a side effect — the layout is more robust now even setting the feature aside.
  • The driver reported instead of patching. Fable hit the locked design's first hole, stopped, and said so with a proposed fix rather than deviating silently. That is the behaviour that makes a spec error cheap.
  • Deriving tooltips beat writing them. One loop replaced 25 hand-edits that would have drifted.

What could be better

  • The design should have been rendered before it was locked. Both spec errors were containment/scoping questions that a five-minute screenshot would have answered. Design review for a visual feature needs a picture, not just prose.
  • “Hide X when collapsed” is an incomplete instruction. It must name the container. Any class shared between a rail and a flyout gets hidden in both. Worth carrying into the next collapse-style feature.
  • Badge counts vanish when collapsed. Watch, Drift and Off-Script carry unread counts inside the label, so a collapsed operator loses the at-a-glance alert. Known and accepted for v1, not discovered later.
  • The flyout's measured top can drift. appswSet() opens the menu by class toggle without a re-render, so if the operator scrolls a long collapsed rail and then opens the switcher, the menu appears at its pre-scroll position.

What’s next

The DIA — dianoia: pure intent, verified, enacted

Three files, three owners → one gate (biRT) → a deterministic run. The model proposes, the substrate disposes. For review.

.pi — operator .si — substrate .sm — the C build .seal / biRT gate drift → refuse

Three files, three owners

  • .pi — the operator wills it: demands + the exact words we say. Never how.
  • .si — the substrate plans it: units that each cite a demand and bind a skill. Claude drafts, the operator approves the diff.
  • .sm — the C build owns it: the generated catalog of bindable micro-ops. A .si may bind only a pub row.

biRT — the gate (verified == executed)

Six checks join .pi ↔ .si ↔ .sm ↔ .seal both ways. Any break — an unauthorized mechanism, a dropped demand, a tampered word, a broken key-flow — and pi_run refuses (exit 5) before a single unit runs. Drift can’t reach production; it’s caught at the door.

Why it can’t hallucinate

The engine is pure C over the run ledger — biRT, the resolver, the fold, render, recovery — all $0, model-free. understand() is a WordNet-backed decoder: it classifies fixed input against a fixed lexicon, it never generates tokens. Same input → same bytes, forever. That is Tier-0.

Model proposes, substrate disposes

A jacket (e.g. a Vertex panel) may act as a sensor, but every decision is made in C over what the sensor returns — the fold in pantheon. The last sensor is being driven to Tier-0 ($0, decoded by understand()). The north star: no model in the loop at all.

Design — Proof of Conduct

biRT proves a card can't betray its intent before it runs. This proves a specific run didn't — a per-demand receipt pi_run emits at the end, independently checkable, for the record. Proof-before meets proof-after. Opus authored; two Fable5 adversarial round trips.

1. Need

Purcius ships intent as law: a .pi is numbered demands, and biRT already refuses to run a card whose units don't cover every demand, whose binds aren't in the catalog, whose word-seals don't match. That is a universal proof — for all runs of this card, structural violation is impossible. But it says nothing about a particular run. When an operator, an auditor, or a customer asks "did that run actually obey D5? did it really never contact the guest on the illness path (D6)? was it truly once-only (D12)?" — today the honest answer is "trust the logs." For a system whose whole pitch is trusted, deterministic, LLM-free intelligence, that gap is the product. We need a durable, third-party-checkable proof of conduct: per demand, per run, a verdict and its evidence — verified by re-derivation, not by re-running the DIA. Independence is anchored today by replication + the Zendesk co-copy; adversary-grade "without trusting us" arrives with operator-key signatures (phase 2, named in the limits).

2. Raw User Stories

  • As an operator, I want every run to leave a receipt: for each demand, satisfied / not-reached-legitimately / violated / incomplete, with the evidence.
  • As an auditor (or a customer, or a regulator), I want to verify that receipt myself — holding only the card + the receipt — without re-running the DIA and without trusting the operator.
  • As the mission, I want the $0 deterministic units to be replay-provable (re-derive byte-identical output) — the LLM-free advantage made checkable, not asserted.
  • As a DIA author, I want a "never" (D6 illness never reaches the guest; D15 never direct) to be proved, not merely claimed.
  • As an operator, I want a run that died silently to be an alarm, not a blank — a missing receipt is itself a finding.

No new file format — the exit-gate topology + why: already encode which demands are negatives; deriving beats declaring.

Proving a "never" (Kind N) — three layered closures

  • Enumerable event universe. Verified in code: pirun_advance emits the run event before it dispatches the handler, on every path — no handler acts without first appearing in the trace. So "reply_send never ran" = "no run event for send in a sealed 1..N." Two closure conditions the design makes explicit, or the "never" leaks: (a) flushed trace — the trace lands in an mmap store; trace_ev must ids_flush after the run event and before dispatching any externally-visible .sm op, so a crash can't leave an effect that happened with no event that records it (write-ahead trace). (b) this run-id only — the universe is one run's trace; a fan-out (dispatch_each) runs children in separate child stores, so each child emits a trace event carrying its child run-id and every Kind-N scan is scoped to the run-id it names — a parent's clean trace never proves a child's "never."
  • Catalog closure. A unit can only bind a .sm micro-op (biRT refuses otherwise); the .sm is the complete list of ways this card can touch the world. "Never direct" (D15) = channel enumeration: none of the catalog's comms ops is a direct-to-guest path. Proof = .sm hash + biRT verdict + binary hash.
  • External corroboration. Zendesk itself — no public comment, no follow-up — queryable by anyone, on a system we don't own.

Honest boundary of every Kind N: we prove the system never did it — not that no human with a mail client did — and only for this run-id, over a flushed trace. The Zendesk external check is load-bearing, not decorative: it backstops the crash window between an effect landing at the vendor and its trace page flushing.

The receipt — what pi_run emits, for the record

At terminal state (DONE / EXITED / FAILED / held), one final fold over pi->clauses (biRT's own loop) — so no demand is ever missing. Verdicts: satisfied · not-reached (legitimate: a citing unit sits after a gate that exited — evidence = the gate's seq) · violated · incomplete (held/failed — interim, re-issued on resume). Triples in the IDS ledger, append-only, new subjects:

(run:R:proof:D5,  verdict, "satisfied")   (…, kind, "construction+witness")
(run:R:proof:D5,  evidence,"seq:7,9 illness.detected=false fold=pi_run-c vh:illness.verdicts=3fa21c07")
(run:R:proof:D6,  verdict, "not-reached") (…, evidence,"gate:illness_escalate seq:9 illness.exit=false")
(run:R:proof:D9,  kind,    "replay+witness")  (…, evidence,"in:alert.feedback#4a1b out:reply.body#9c33 slots:tsv#… tmpl#…")
(run:R:receipt,   card,"mendo-nps-detractor-triage")  (…, pi_h,…) (…, si_h,…) (…, sm_h,…) (…, bin_h,…)
(run:R:receipt,   seq_max,"23")           # closes the event universe for Kind N
(run:R:receipt,   birt,"verified units=14 demands=15 words=5")
(run:R:receipt,   seal,<FNV over all proof triples + the trace slice>)

Where it lives: (a) the run ledger, replicated by the auto-sync IDS — the durable machine copy; (b) a second private note on the alert ticket (the Shredder pattern) — one compact line per demand + the seal, where humans read, co-timestamped by Zendesk. Our copy and Zendesk's must agree — the anchor.

Independent verification — without re-running the DIA (no effectful external call, no irreversible step, no model, no spend — the read-only vendor/Register queries in steps 6–8 excepted; only pure $0 units are deliberately re-derived, because they safely can be). dia_attest recomputes each demand's verdict from {trace, ledger, card} — it treats the receipt's verdicts as claims under test, never as inputs, so a self-consistent-but-lying receipt (a "not-reached" citing a gate seq that actually passed) is caught by re-derivation, not a seal check. What "recompute" means by kind: for Witness/Replay it is literal re-derivation; for Construction (D5/D6, N's .sm-closure leg) it is re-verify the premises — topology, hashes, biRT verdict — the theorem itself is cited by hash, not re-derived (see Self-certification). The bundle: {.pi, .si, .sm, .pi.seal, receipt, trace slice, + the ledger data-plane slice — full values live there; trace out events truncate to 60-char previews}. Steps: (1) re-run dia_verify; (2) receipt demand-set == .pi clause-set, its units ⊆ the .si why-map (a receipt naming an unbound unit is self-evidently forged); (3) trace conformance — does the sequence obey the plan's topology (cursor monotone, gates honored, exit ⇒ no later dispatch)? (4) recompute the seal; (5) Kind R: replay the pure units from recorded input + slot-data hashes; (6) Kind I: query the Register; (7) Kind N externals: query Zendesk; (8) fan-out: enumerate child run-ids from the dispatch events and require each child's receipt to exist — a parent never certifies a child it didn't chase.

Out of scope: proving model correctness (we prove we asked + gated, not that the model was right); a keyed signature (phase 2 — FNV is drift-, not adversary-evidence); deep cross-card receipt chains — though the direct parent↔child run-id link IS in scope and required (dispatch_each must emit each child's run-id in-band, or a fan-out's Kind-N proofs leak); anything a human does outside the system.

6. First Move

The receipt emitter as a terminal fold over pi->clauses for ONE live run: emit a verdict + evidence per demand into the ledger, stamp pi_h/si_h/sm_h/bin_h at start, add value-hashes to out events, seal it. Prove it by handing {card, receipt, trace} to dia_attest on a second machine and getting "conforms" — without re-running the DIA. That one loop is proof-after, real.

Into the plan: write-ahead trace (ids_flush after the run event, before any effectful .sm op); dispatch_each emits each child's run-id (the in-band parent↔child link Kind N needs); full value-hashes on out events + the ledger-slice in the verifier bundle; the dia_attest verifier that recomputes; the receipt-note render on the ticket; then Kind R replay for the pure units, and Kind I once the Register lands.

The honest limits — provable-for-the-record vs asserted

  • Model correctness is outside the boundary. D4/D5: we prove we asked the declared roster, got per-model verdicts, gated unanimously in our own C. We cannot prove the models were right — only that the safety envelope held (any doubt → human). The receipt says panel-verdicts: witnessed, not adjudicated.
  • D13 is claim-proved, not enactment-proved. biRT sees the config; the requester is set by the upstream alert-create card. Full proof needs the receipt-chain across cards (parent-run reference — designed, not yet specced).
  • Cross-run invariants block on the Register. D8/D11/D12 are provable per-node today (vault row, bridge "already-noted"); mesh-scope waits for auto-sync IDS. The receipt says satisfied (node-scope) until then — no overclaim. (The vault's read-modify-rewrite is single-process-atomic, not concurrent-atomic — named.)
  • FNV is drift-evidence, not adversary-evidence. A forger who rewrites data + seal isn't stopped by FNV. Adversary-grade "for the record" needs the operator-key signature (phase 2). Until then, tamper anchoring = replication + the Zendesk co-copy (falsify all three in agreement).
  • Self-certification. The receipt's emitter (pi_run) is its own subject, and bin_h is self-reported — a compromised binary stamps the honest hash. This is why dia_attest recomputes verdicts rather than trusting them: forgery then requires a fully self-consistent forged trace and the Zendesk co-copy and the mesh replicas agreeing. Construction proofs (D5/D6, the .sm-closure leg of Kind N) remain conditional on bin_h being honest until external binary attestation + the operator-key signature land (phase 2).
  • Negatives are closed-world only. The trace + .sm + binary hash close the system's world; a human bypassing the system is out of scope, and the wording says "no system path delivered X."
  • Held/failed runs get interim receipts. incomplete is first-class; a run that dies with no receipt is itself an alarm the sweep detects (run record exists, receipt subject doesn't).

1. Does Access policy: Open get a warning?

No. This surface reports; the audit judges.

Open is the least locked-down option and on a kitchen-server port that matters — but SW-PORTSEC already owns that verdict, and it counts access ports without a policy today. If this table also renders an opinion, two surfaces can disagree about the same port and the operator has to work out which one is lying.

So the visual rule is quiet = Meraki's default, lit = somebody configured it. That reports deviation, which is a fact, without ranking safety, which is a judgement. The audit's verdict stays one click away in its own tab.

2. Admin-disabled vs link-down

Status today shows Meraki's live link state. A port that is administratively enabled:false reads exactly like one that's merely unplugged — "Disconnected" — and that is true but misleading.

Position (navigator's, adopted — it corrected the driver): a different WORD in the Status cell, same grey. Not a coloured badge.

The driver's first pass put a red DISABLED badge in the Port cell. That was wrong, and wrong by this document's own rule: a disabled unused port is good hygiene, and painting it red is exactly the judgement §1 forbids. The driver argued "report, don't judge" and then judged.

So: ⌦ Disabled in the Status cell, in the same #777 grey family as Disconnected — different word and glyph, because "administratively off" and "unplugged" must never be confusable. Admin state overrides link state in that cell, because it is the causal root: a disabled port cannot link.

That does three things at once: it answers "how do we find it" (the roster already names it), it supplies the exact join key the Systems Manager lookup needs — the v2 design's IP-match fallback for a wired host — and it means the Host firewall button can render on roster-matched hosts rather than guessing from a fingerprint. Navigator's find; the driver missed it entirely.

Position: invent nothing further. One ghost button in a 48-row table is the landmark — the eye finds the only interactive element in the Description column immediately. A filter for a one-row result is machinery; a pin invents a persistence feature nobody asked for. Ctrl+F covers the rest.

4. The three answers, and provenance

There are two independent axes, and collapsing them would be dishonest.
  1. Did we find the right host? A wifiMac match is deterministic. An IP match is a heuristic — right in practice for a static-IP server, but still an inference.
  2. What did that host report? Firewall on, off, or nothing.
So: the pill text carries the state, the border style carries the identity confidence. A firewall that is definitely ON, on a host we matched by IP, renders as a green pill with a dashed border and the words matched by IP — certain state, inferred identity. Collapsing that into one solid green badge would launder a guess into a fact.

Every answer is stamped with lastConnected, because this is last-reported state, never live state — the agent's word, relayed.

Before click: a quiet ghost button, shown only when the OS fingerprint says Windows — the fingerprint decides whether the button appears, never what the answer is. While loading: the console's existing .spin.

5. Where the ⛔ Systems Manager gate shows

Position: if the org has no SM, the button does not render at all — and one line at the top of the pane says why, once.

A disabled button on every Windows row is 48 pieces of noise repeating a single org-level fact. State a fact at the level it is true. Toggle it in the mockup to see both.

6. What this must not become

The new ACCESS POLICY badge lands directly beside VLAN cells that already carry live write pencils (.vlanedit, :1571-1572), backed by a working POST /meraki/port-vlan. It is one "just make it a dropdown" from writable.

Blast radius: re-VLANing or policy-flipping the kitchen server's port takes POS and KDS down mid-service. A MAC-allow-list write that omits the server's own MAC is a lockout that survives a reboot.

So the badges render with no data-target, no button class, nothing the delegated click handlers can find. Read-only here is the posture, not a phase.

1. Intent

Two read-only additions to a nine-column table that is already dense, in a console whose established law is that nothing scrolls sideways. The axes resolve exactly as they did for Drift — serious, dense, abstract, bold-by-colour, responsive, restrained — because this is the same product and the same operator. Top two traits: dense and serious. The one real contradiction is dense × the need for three new facts per row; it resolves the way the console already resolves everything: badges carrying weight, not columns carrying width.

2. System rules

Colour

Inherited verbatim from the live :root (index.html:10). No new base colours. --bg #0a0a0a · --surface #141414 · --line #262626 · --accent #6FC3DF · --dim #888 · --ok #7CFFB2 · --warn #ffce85 · --bad #ff6b6b.

The one new rule is semantic, not chromatic: dim = default, accent = configured, warn = trunk, bad = admin-down. Four states, four existing hues, zero invention.

Spacing & type

Base 4px. Badge geometry is the shipped .lvl exactly — font-size:.58rem, font-weight:800, letter-spacing:.5px, padding:1px 5px, border-radius:4px — plus margin-left:5px so badges sit off the port number without a new cell. Table cell padding stays 5px 8px. Machine values stay ui-monospace, Consolas; prose stays the system stack.

Density

Target: a 24-port switch still fits one viewport, unchanged from today. Badges add zero row height because they are inline at a smaller font than the cell. Zero new columns means zero new horizontal pressure — the constraint is satisfied by construction, not by tuning.

Depth

Flat. Borders and surface value only. The badges are 1px outlines, not chips with shadows.

3. Component behaviour

Badges — inline in the Port cell, never wrapping to their own line on a 24-port table; uppercase, 800-weight, tiny. Not interactive, deliberately: no hover promotion, no cursor change, nothing a click handler can select.

The Host firewall button — the console's ghost button (.renameit/.vlanedit recipe: transparent, 1px --line, hover promotes border and text to accent). It sits on the .cline client row, inheriting the flex-wrap that already keeps a name and its pencil together.

Result pills — replace the button in place. State in the text, identity confidence in the border style, provenance in a dim italic suffix, freshness always present.

The legend — one block under the table, in the coverage-note treatment Drift uses, explaining the quiet/lit rule. Without it, "lit" is decoration; with it, it is information.

4. Interaction

Transitions 120–150ms, matching the shipped values, and only on the button's hover. Badges never animate — they are state, not events; motion on state teaches you to watch for motion.

Feedback: hover promotes border+text to accent (buttons only). Focus is the console's existing :focus-visible 2px accent outline. Loading is .spin plus "asking…". Failure keeps the button and appends a dim reason — it never silently reverts to unasked, which would read as "nothing happened".

The click is a read. Nothing here mutates, so nothing needs a confirm step — which is precisely why the badges must stay unclickable: the moment one of them is interactive, someone will reasonably assume this table edits.

Carried risks for the build

  • Column sorting. The VLAN cell gains badge text, and SORTSTATE (index.html:771) may sort that column on whole-cell text. Either append the chip after the number so a numeric parse still wins, or give the cell a data- sort key. Verify at ~b — this is the most likely thing to break quietly.
  • Does Meraki's port-status endpoint already return a literal Disabled for admin-down ports? If so, .st-off becomes pure styling over data we already have, and the enabled projection is belt-and-braces rather than the source.
  • Custom access policy #N ships unexercised — no port in this org has been observed using one. The first #N that renders is the Rule-7 trigger for the name-resolve call.
  • Trunk native VLAN. Meraki's editor labels the number "Native VLAN" on trunks; our column shows a bare number. A tooltip fix if operators ask.

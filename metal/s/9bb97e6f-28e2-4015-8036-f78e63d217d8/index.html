The simplest pure build

Purcius bridge auth — ship the approved pure design with the least machinery.
~p (re-run) · paired: Opus + Fable · design approved → v3 PURE · diagram

Intent

The design is locked: Ed25519, the bridge holds only public keys, the private key never leaves the prime, the signature binds the whole request. This plan is the simplest build that keeps every one of those properties — we shed the fiddliest parts (native P/Invoke, the shared-state nonce ring, redundant canonical fields) and refuse the one "simplification" that would quietly reopen a hole.

The signed pre-image (final, simplified)

preimage = LF("purcius-bridge-v1")   domain sep
         ∥ LF(audience)               "zendesk-bridge" | "gcp-bridge"
         ∥ LF( sha256(method | rawpath+query | body) )
         ∥ LF(ts, 8 bytes LE)
         ∥ LF(nonce, 16 bytes)
         ∥ LF(key_id)                 "hk-01" | "vegas-01"
   where LF(x) = uint64_LE(len(x)) ‖ x     length-framed — unambiguous, NUL-safe
sig = Ed25519_sign(prime_private_key, preimage)     64 bytes

The bridge rebuilds this pre-image from the exact received wire bytes, verifies the sig against the key_id's pubkey, checks |now−ts| ≤ 5s, and (mutating verbs) the durable nonce-seen. It authorizes only on fields present in the pre-image.

Build order (ship this)

1 · Signer (pi_run, C99) Vendor Monocypher (ed25519.c beside crypt.c, pinned). Build the length-framed pre-image + sign. Generate per-prime keypairs; private key 0600, never leaves the box; extract pubkeys.
done = a prime prints a sig a throwaway verifier accepts.
2 · KAT (CI) Commit the cross-language vector test — Monocypher signs the RFC-8032 vectors, NSec verifies — plus a must-reject corpus (S≥L, non-canonical R, wrong length, all-zeros). Pin both library versions.
done = KAT green + every bad vector rejected, in CI.
3 · Verifier (bridge, C# + NSec) Load the pubkey allowlist by key_id. Rebuild the pre-image from received wire bytes (hash the raw body before ASP.NET re-serializes; raw path+query). Verify sig → ts window → durable nonce-seen on mutating verbs. Authorize only on signed bytes.
done = a real prime sig passes; a forged/replayed/tampered one fails.
4 · Phase A — additive + telemetry Bridge accepts sig OR daily. Emit auth_method, verify pass/fail, ts-skew, replay-hit, path-skew (catches any GFE path normalization) — never the sig. Deploy. The daily sweep never notices.
gate: telemetry live; watch sig-present climb.
5 · Phase B — flip pi_run to signing HK first behind a pre-flight 200 probe (a read call must return auth_method=sig before any mutating traffic relies on it), bake a UTC-midnight cycle, then Vegas.
gate: both primes on sig, zero daily, a full day.
6 · Phase C — fail closed Rip the daily branch on zendesk-bridge + daily_key() from pi_run (all sites). Refuse all without a valid sig.
done = a forged yyyyMMdd~go is rejected, verified from outside.
7 · Fast-follow — gcp-bridge twin Repeat A→C for gcp-bridge (own audience + pubkeys). Time-boxed to this change window; spend-cap the Vertex lane until its daily branch is gone.
done = both services reject the daily key.

Constraints

  • Monocypher vendored (pinned version+SHA); NSec pinned; plain Ed25519 both sides.
  • Authorize only on signed bytes — never an unsigned header.
  • Per-prime keys; private key 0600, never transmitted, never logged; pubkeys committed to the repo.
  • Trust root is now the signed-commit + deploy gate (Project-DoD P4/P5) — it must not weaken.
  • Never break the 15s sweep: additive-first, pre-flight probe, HK before Vegas, fail-closed only after zero-daily proven.

Unknowns (named, per Rule 6)

  • GFE path/body normalization — does Cloud Run's front end rewrite %2F////%7E or the body before C# sees it? If so the hash skews. Mitigation: hash received wire bytes; Phase-A path-skew telemetry surfaces it before cutover.
  • Raw-body capture in the C# jacket — must read the stream before model-binding; unverified until we wire it.
  • NSec availability in the jacket's .NET target — assumed clean; confirm at step 3 (fallback: BouncyCastle, heavier).

When to revisit (the v2 triggers)

  • Phase-A telemetry shows path-skew verify-fails → canonicalization needs pinning before Phase B.
  • A new non-idempotent mutating verb is added → it must be added to the durable nonce-seen set (or it's replayable in-window).
  • The cross-language KAT ever reveals drift → revert S3 to P/Invoke the one C verify.

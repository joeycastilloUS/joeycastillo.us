zendesk-bridge — multi-sandbox addressing

The A/B needs two separate Zendesk sandboxes through one bridge · design reconciled Opus + Fable (~i~d~p, 2026-07-23) · Phase 0 shipped

The whole picture

The bug this fixes

Today both arms would key the HMAC on the literal "sandbox". Ticket 741 in arm A and ticket 741 in arm B would derive the identical code — two different guests, one coupon. That is a straight D2 violation ("never double-issued"), and it is near-certain rather than theoretical: both sandboxes are fresh, with overlapping small ticket ids.

The fix: the HMAC's env component becomes the slot name. Arm A's name stays the literal "sandbox" — so every already-issued code survives byte-for-byte — and arm B derives under "sandbox-b". Collision becomes impossible by construction.

Why the name and not the subdomain (Fable's catch, and it is load-bearing): a Zendesk sandbox rebuild mints a new numeric subdomain. Subdomain-keyed codes would silently re-key on every rebuild. Names are stable; subdomains are not.

Proven, not asserted

Derive("test-secret", "sandbox",   "741")  =  MENDO-42WDBFN2
Derive("test-secret", "sandbox-b", "741")  =  MENDO-N8ZCXG72   <- different arm, different code

CI golden lock (Phase 0, shipped):  131/131 green
  - arm-A "sandbox" codes frozen        (drift fails the build)
  - cross-arm divergence guard          (D2 holds across arms)

Two latent bugs found on the way

Silent prod readToday, env=sandbox with the sandbox unconfigured falls through to the prod client — you ask for sandbox, you get production data. Closed by fail-closed PickSandbox.
Unqualified ledgersSentDrafts and PromoLedger key on raw ids, so a reused draft_id across arms would false-dedupe. Both get the slot-name prefix.

Method

Paired per kernel Rule 1: Opus and Fable ran independent ~i~d~p passes and reconciled. Both converged on the slot registry; Fable's pass won on three specifics (name-keyed HMAC, the silent-prod-read bug, unqualified ledgers). One disagreement is unresolved and belongs to the operator: whether an unknown non-empty env should fail closed with 503 (Fable, and the driver now agrees) or fall through to prod as documented today.

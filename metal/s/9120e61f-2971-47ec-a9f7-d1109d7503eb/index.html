Trace engine port, wave 1

Everything in the Tracer handoff that does not need the email grant — built, verified against the source org, and live

Build brief · live at argus.com.ai/app → Salesforce → Case Patterns · 2026-07-27

What wave 1 is. The handoff describes a trace engine: code does the deterministic work first, and the model gets exactly one job. Most of that needs the email conversation we still cannot read. Four things did not, and all four were things we were already getting wrong. They are done. Every field named in the handoff was tested against the live org before any code was written.

1. A match now says how far to trust it

Previously a case either matched a pattern or it did not. The handoff's contract is sharper, and the reason is practical: the consumer needs to know whether it is allowed to disagree.

hardAn exact error string fired. Authoritative — do not re-route it.469
fingerprintSeveral signals corroborate. Strong, but still confirm against the evidence.5
candidateA lead. Verify or rule it out, and carry what is missing.478

This changed nothing about what matches — 933 cases before and after. It only labels how much weight each one carries. Shown per pattern, badged per case, with a legend on the pane stating that the tier is a measure of authority, not of likelihood.

2. The coverage rate was inflated, and now isn't

The tab reported 2.2% of the corpus. The handoff's second lesson says to state coverage against minable cases only, and it is right: a large share of the corpus contains nothing to mine.

The rate is now 3.6% of minable rather than 2.2% of everything, with the exclusions and the rule printed on the pane instead of buried. Roughly two of every five cases have no text worth matching, and any rate quoted against the full count silently assumes they do.

3. A pull that survives a revoked permission

The label taxonomy — type, reason, closure state — is permission-guarded in this org. It was being requested in the same query as everything else, which means one revoked grant returns an error and the entire pull dies.

That is not hypothetical here. Two other fields on the same object are already blocked on our credential, so we know the guard is live and enforcing.

Those fields now go in a separate, wrapped query and are merged on afterwards. If the grant is ever lost, the cases still land with that column blank and the failure is reported once. A blank column is a bad day. A dead pull is a lost night.

These reach the corpus on the next re-land, which is still waiting on the stager port.

5. Also added: a version stamp

The bake now records a fingerprint of the compiled pattern library. If the library moves and the signal list does not, that drift is visible rather than quietly producing confident stale answers. The handoff calls for exactly this, and it is the same class of failure as the inflated denominator: a number that looks fine and is not.

6. What is next, and what it waits on

WAVE 2The deterministic blocks. Evidence cleaner, quote-strip, decoder with source-line receipts, escalation gate. Pure functions, no model anywhere in them. Portable now — though quote-strip only earns its keep once there are email threads to strip.
WAVE 3The output contract. Six fixed sections, confidence gate, stakes routing, output modes, one streamed model call. Not worth running until the grant lands — without the conversation, a trace has only subjects and descriptions to reason over.
BLOCKERRead access to the email object. They read it on 100% of cases in the same org on a different credential. We get an error. This is a permission grant, not engineering, and it gates the half of the port that matters most.

7. Where this ends up better than a port

The handoff says so itself, and it is worth repeating because it sets the target. Their pattern section matches against a nine-entry library. Ours sits on a 42,402-case corpus with a ranking engine and the label spine they have just adopted. Their trace answers "which pattern is this." Ours can eventually answer "here are the fourteen most similar resolved cases and how each one ended."

The port makes this a triage tool. The corpus is what makes it a better one. Wave 1 is the unglamorous half of that — correct denominators, honest verdict tiers, a pull that does not die — and it had to come first, because everything downstream inherits those numbers.

8. How to check it

  • Open the tab. The headline now reads of minable cases, and every matched case carries a tier badge.
  • Open any pattern — the hard / fingerprint / candidate split is on its line.
  • The denominator, its exclusions, and the rule that produced it are printed under the stats, not hidden in a commit message.
  • Every figure here was measured against the live org before the code was written, not after.

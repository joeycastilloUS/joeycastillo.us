The new single .pi for the Mendo NPS-detractor flow: illness → escalate humans by email through Zendesk · else → the deterministic $0 Zora recovery. Supersedes mendo-app-survey-autoresponse (v10, retired, kept just-in-case). env sandbox · prod DISARMED. Updated 2026-07-15: the panel's input is REDUCED ATOMS (nous understand()), not prose — proven by an A-B bench (§6) against the raw lane before arming. Panel = three Gemini models, NO Claude (jc order): vertex-gemini + vertex-gemini-pro + gemini-2.5-flash-lite.

PRIVATE / INTERNALSANDBOXONE INFERENCE UNIT

1 · Need

The retired card auto-replies to every detractor with the Zora "We're Sorry" template and an IMSORRY code. Its own header names the gap that kept prod disarmed: "Food-borne illness = its OWN detection build (deferred)… prod stays DISARMED until illness detection lands. When built: never a reply, never a code. Hard law."

An illness report answered by an automated coupon is the one unforgivable send. A sick guest needs a human — Guest Relations, follow-up, possibly a health-department obligation — not a $10 code from a persona. This card is the deferred build: triage first, recover second.

Panel input — reduced atoms, not prose (jc order 2026-07-15)

The panel is sent reduced atoms, never prosed-up data. reduce_feedback runs nous understand() on the guest feedback and emits the reduced form — atoms + entities + actions + constraints, serialized as flat key=value lines. That reduction IS the panel prompt payload. Why it wins: the models judge the same distilled facts every run (no prose noise, no rhetorical padding), the tokens are fewer (cheaper panel), and the reduction is deterministic — the same feedback always produces byte-identical panel input, so verdict variance can only come from the models, never from the framing.

6 · The A-B Bench — prove reduced ≥ raw before ship jc order

This is the A-B test jc asked for. Two lanes, SAME 3-Gemini panel, SAME labeled sandbox corpus, one run each. The reduced-atoms lane must score at least as high as the raw-prose lane on illness detection before production arms — if it doesn't, the reducer is fixed and the bench reruns; the lane decision never flips.

Runtime (section 5) ships ONE lane — Lane B, reduced atoms. Lane A exists only inside this bench, as the control the reduced lane must beat or tie. The panel, the fold, and the corpus are identical across both lanes so the ONLY variable is the input form (prose vs atoms).

Assertion under test: the reduced lane scores at least as high as the raw lane at illness detection. Both lanes hit the SAME panel (3 Gemini models, unanimous-safe fold) over the SAME labeled sandbox corpus:

  • Lane A (raw): panel input = alert.feedback verbatim prose.
  • Lane B (reduced): panel input = reduced.atoms from understand().
  • Corpus: labeled sandbox tickets — illness-worded positives (nausea, food poisoning, "got sick after") and clean-complaint negatives (app trouble, wrong order, slow service), seeded via /zendesk/alert-create.
  • Score: per lane — recall on positives FIRST (a missed illness is the unforgivable miss), then precision on negatives, then cost per verdict. Recall is the gate; precision and cost are the tiebreakers.
  • Acceptance gate: Lane B recall ≥ Lane A recall AND Lane B precision ≥ Lane A precision. If reduced loses on either, the REDUCER gets fixed (atoms are dropping signal — find which token classes) and the bench reruns. Raw is the control, never the fallback lane.
  • Decided regardless of bench drama: production uses the reduced atoms. The bench exists to prove the reduction preserves (or sharpens) the illness signal before prod arms — not to pick a winner at runtime. The card ships ONE lane.

The escalation lane (zendesk-bridge, to be built — designed here, not built)

A new sandbox-only lane beside /zendesk/alert-create / /zendesk/recovery-send, same discipline: sandbox client only (503 if ZENDESK_SANDBOX_* unset), service-built tickets.json payload, never raw caller passthrough.

  • POST /zendesk/internal-alert — body: { recipients[], store, nps, order_id, guest_email, feedback, reason, alert_ticket_id, draft_id }.
  • Builds: subject "ILLNESS ESCALATION | <store>", requester omitted (defaults to the API user — the guest is never the requester), email_ccs = the recipients (agents or free-form end-user emails; Zendesk emails both), first comment = store / NPS / order / guest email / verbatim feedback / the panel's reason, comment public so the CC notification fires to the list — the guest's address is in the body only, so no mail can reach the guest. Tag argus_illness_escalation.
  • Idempotent on draft_id = illness-<env>-<ticket>; capture-before; sandbox for the test, prod arms with the card.
  • The recipient list is DATA: the micro-op reads slots/escalation-recipients.txt (one email per line). No names or addresses in the card, in this design, or in any published artifact — kernel Rule 8.

The determinism contract (the reconciliation)

The earlier ruling stands: the guest-facing reply is 100% deterministic, $0, no LLM — Vertex stays OFFLINE for map-authoring on that path, exactly as v10 locked it. illness_check IS live inference — and that is correct here, because its only consequence is emailing humans for review. It can never write guest-facing text, never claim a code, never vary Zora's bytes. The card has exactly ONE inference unit, and it sits entirely on the human-escalation side of the branch. Guests only ever see deterministic output; inference only ever routes to humans. Panel variance is made harmless by policy: under unanimous-safe, any run-to-run wobble falls toward escalation, never toward an unchecked guest reply.

Cost

illness_check is the one non-$0 line: 3 Gemini calls per detractor alert (one short prompt each — the atoms plus a fixed question; sub-cent per alert — three Gemini tiers, dominated by the Pro panelist; Flash + Flash-lite are near-free). Reported per-run in illness.cost_usd and rolled into run.cost_usd by audit. Every other unit is $0.00 (nous C99 + bridges), and gate_handled guarantees the panel is never paid twice for one alert.

Choices — the agreement policy

PolicyBehaviorVerdict
2-of-3 flagsEscalate only when a majority flagsRejected — one model seeing "food poisoning" while two miss it is exactly the miss this card exists to prevent.
Any-1 flagsEscalate when at least one model flagsClose, but silent on the failure modes: a model that errors or returns garbage counts as "didn't flag."
Unanimous-safeRecovery runs ONLY on three clean "safe" verdicts; any flag, any error, any unparseable output → not safe → escalateRecommended. Strictly the most conservative: it subsumes any-1-flags AND treats panel malfunction as doubt. Flag-on-doubt is the brief; a false escalation costs a human a minute, a missed illness is unforgivable. Precision is tuned later with evidence (see Escape Routes), never guessed now.

Also chosen: fail: hold on both triage units — a panel outage or a failed escalation POST pauses the run for the operator. The run must never silently fall through to recovery past an unchecked or unescalated illness.

Choices — the panel input

InputBehaviorVerdict
Raw prosePanel reads alert.feedback verbatimRejected for production — prose carries noise and padding, costs more tokens, and gives the models a different framing per guest writing style. Kept as the A-B control lane only.
Prosed-up summaryAn LLM rewrites the feedback, panel reads the rewriteRejected outright — a second inference unit on the safety path, and a paraphrase can launder away the exact phrase ("food poisoning") the panel exists to catch.
Reduced atomsnous understand() decodes the feedback; panel reads atoms + entities + actions + constraintsChosen (jc order). Deterministic, $0, cannot hallucinate — the same feedback always yields byte-identical panel input. Proven ≥ raw by the A-B bench before prod arms.

Escape Routes

  • Panel unreachable → illness_check fail: hold; the run pauses, the operator sees it, nothing is sent. The 15-min sweep re-offers the alert after the fix.
  • Escalation POST fails on a detected illness → illness_escalate fail: hold; same posture — hold, fix, rerun. Never proceed.
  • False-flag rate too high in practice → measure precision on real sandbox traffic first; only then consider relaxing unanimous-safe to 2-of-3 with the error/unparseable→escalate rule kept. Evidence tunes it; the card ships conservative.
  • Gateway model drift → NousGatewayClient.ListModelsAsync validates panel ids at startup (unknown id → warn); a missing panelist is a not-clean verdict → escalate, never a thinner panel silently.
  • Reduced lane scores below raw in the bench → the reducer is dropping illness signal. Diff the losing cases atom-by-atom against the prose, fix understand()'s token coverage for that vocabulary (offline, deterministic, testable), rerun the bench. The lane decision does not flip — the reducer gets better until it clears the gate.
  • Whole-card rollback → the retired mendo-app-survey-autoresponse.pi (v10) is preserved byte-for-byte as the just-in-case: point the host back at it and the flow is recovery-only again in one config change.

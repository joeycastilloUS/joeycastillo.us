Unit 4 — illness_escalate (D3) · THE ARM-BLOCKER

The one unforgivable send. This unit is a compound slot: procedure AND keyword trigger, both required. The procedure is probabilistic (the model obeys as often as it does); the trigger is the deterministic floor. No gauntlet, no arm, until BOTH exist.

4A — Content → Procedures (paste FIRST, before the promo procedure):

If the guest's message shows ANY sign of food-borne illness — nausea, vomiting, diarrhea, stomach ache, hospital, "got sick", "food poisoning", or any paraphrase, in any language — you MUST escalate to a human immediately. Do NOT reply. Do NOT run any action. Do NOT fetch or mention a promo code. When in doubt, escalate. This rule overrides every other instruction.

4B — Objects and rules → Triggers → Add trigger:

Conditions (meet ALL):
  Ticket        is        Created
  Received at   is        support@guestrelationstestv2.zendesk.com

Conditions (meet ANY) - illness words:
  sick    ill    nausea    vomit    diarrhea
  food poisoning    hospital    poisoned    threw up    stomach

Actions:
  Add tag           skip_ai_reply
  Assign to group   NPS Escalation (human)   [#51689848037908]
WHY THIS TRIGGER CARRIES NO TEMPLATE-TOKEN CONDITION. The earlier draft gated it on "NPS Score" only — but the reply trigger fires on "NPS Score" OR "Guest Experience Alert". An illness email carrying only the second token would get no skip_ai_reply tag and the AI would reply with a coupon to a sick guest. The illness trigger's footprint must cover the reply trigger's footprint — so it fires on illness words alone, scoped only by address.

The escalation group lives in the same account, so Arm B reuses it directly — no second group.

Accept: every illness email escalates → 0 auto-reply, 0 code.
Docs: https://support.zendesk.com/hc/en-us/articles/9424547984026

Unit 3B — the promo procedure (paste AFTER the illness procedure)

Content → Procedures:

When you compose a recovery reply to an NPS detractor, first run the action Fetch Mendo recovery promo code with this ticket's ID. Include the returned code in your reply exactly as given — never invent, alter, or reuse a code. If the action fails or returns no code, send the reply WITHOUT mentioning any code. Never mention the action, the endpoint, or the fetching process to the guest — just include the code itself. Only on a genuine recovery reply — never on an illness case (the illness rule always wins).

The gauntlet

Corpus: be/pi/mendo-illness-gauntlet.tsv — 16 rows: 11 illness (3 explicit-keyword, 4 paraphrased with no keyword, 3 oblique/misspelled, 1 Spanish) + 3 clean detractors + 2 neutral.

The 4 paraphrased + 3 oblique rows are the real test: the keyword trigger is brittle on paraphrase by design, which is exactly what the procedure layer is measured against.

Gotchas — all of them

Chip, not bracesCustom-action Body uses the {+} chip. Typed {{ }} ships as literal text → 400.
No nps@, no hello@ on v2One address only. A trigger on either silently never fires.
Shared trigger spaceEvery Arm B trigger MUST carry its Received at condition or it fires on Arm A. Arm A's existing triggers still need a brand-scoping audit.
POST, not GETpromo-claim is a claim. GET → 405.
Frozen HMAC keyThe slot name IS the key; arm A stays the literal sandbox forever.
Strict mode stagedenvStrict=false today; missing env takes the legacy default and logs CRITICAL ENV-MISSING. Under strict, an env-less action 400s and the auto-response stalls silently — visible only in Zendesk's action log.
Requester is the vendor systemOn real feed tickets the requester is mendonps@mendocinofarms.com; the guest address is body-only. Native Zendesk replies to the requester — keep as an honest A/B caveat on D1.
Republish resets editsTrigger-condition customizations can be lost when the agent is republished. Republish, then re-check your edits survived.
Cost asymmetryEach contained B-arm reply bills as an automated resolution (~$1.50–2 + the Advanced add-on); escalations free. Argus is $0.
Burn-at-redemptionDerivation gives never-double-issued; D2's "never reused" needs a burn mechanism that does not exist yet. Must be named in the DIA before arming.

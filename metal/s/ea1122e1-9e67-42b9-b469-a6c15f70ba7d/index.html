Bottom line. The Meraki feature set is built and quiet — network view, all-SSIDs, PoE, template bind, 34-check security audit, action plans with remediation executors, and the device watcher all exist in code and shipped. What is open on Meraki is almost entirely auth / ops / hardening work that happens to live inside meraki-bridge, because bridge/ hosts 10 of its 35 routes as identity and ops — a live violation of the repo's own one-service-per-source architecture. Before any deploy touches meraki-bridge, the CI fork must be reconciled: the repo ARCHITECTURE.md names as canonical is six weeks stale and would roll the live service back past all auth code.

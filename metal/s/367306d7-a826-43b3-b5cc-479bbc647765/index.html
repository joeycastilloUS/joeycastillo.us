The Triage Manager Console

Let the Mendo support manager tune the NPS detractor triage — safely, in the sandbox, without touching anything else.
Proposal · for the Mendocino Farms IT / Support team · paired: Opus + Fable · verified against the live .pi

The idea

Today, changing how the triage behaves — the coupon wording, who gets the escalation — means an engineer edits the intent file. This proposal gives the support manager a chatbox to make those changes themselves, in plain English, with three hard guarantees: they can only change the parts you allow, every change is proposed and approved before it takes effect, and it only ever touches the sandbox — never production, never any other system.

What the manager does

On a "Manage the Triage" tab, the manager types what they want — "make the coupon $15," "add Maria to the food-safety alerts," "soften the apology wording." The assistant replies with the exact change and a before/after. The manager clicks Approve. It deploys to the sandbox and says "deployed — fire a test." They post a test NPS on the same page and watch the new behavior. That's the whole loop.

Why it's safe — the model never touches a file

The manager is an untrusted end-user, so the design splits interpret from act:

manager types  ─▶  scoped AI (READ-ONLY, this .pi only)  ─▶  {op, value}   (just a proposal, never an action)
                                                                   │
                                              deterministic code (no AI)  ─▶  validates vs your allowed menu
                                                                   │            (unknown op → reject, out-of-bounds → reject)
                                                                   ▼
                                              edits the .pi itself  ─▶  deploys to SANDBOX only

The AI can only propose a change picked from your menu — it cannot edit a file, run a command, or reach anything else. Deterministic code does the work, and its deploy target is the sandbox by construction — there is no production path in it to misuse. Free-text fields (like the apology wording) are written as data, not instructions, so a crafted message can't smuggle in new behavior.

The flow

1. Manager types a change in plain English.
2. Assistant proposes the exact edit + a before/after of the affected lines.
3. Manager clicks Approve (or types "approve").
4. Deterministic code validates, edits the intent, and deploys to the sandbox.
5. Manager fires a test NPS on the same page and sees the new behavior. Rollback is one command.

Scope — what the manager can never do

  • Change any knob not on your allowed list — the code rejects it.
  • Touch the illness-detection logic, tags, sender identity, or arming (unless you give them).
  • Reach production, any other file, the mesh, or any other system.
  • Deploy without an explicit approval on that specific proposal.

The one decision from you

Which rows does the manager get? My read is the four give rows (recovery reply, recovery subject, escalation recipients, escalation subject). Confirm or adjust that cut and each becomes one bounded operation in a small mendo-triage-ops.json — the only file that defines the manager's power. Adding one later is a single line, no code.

Definition of done

  • Manager types an allowed change → gets a proposal + diff → approves → it deploys to the sandbox → they test it, all from one page.
  • An unallowed or out-of-bounds request is refused by the deterministic layer, not by the AI's goodwill.
  • No production path exists in the applier. Text fields are written as data (hostile-string tested).

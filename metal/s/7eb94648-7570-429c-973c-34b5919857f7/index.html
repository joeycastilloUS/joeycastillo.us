How the card shipped — and where allow: went

Two questions. The second has an answer nobody expected.

Paired concurrent per Rule 1. Both passes converged; the load-bearing measurement was then re-run independently by the driver against the real files.

Q2 first, because it changes the plan

The allow: lists never reach the runtime. Not ignored — destroyed.

dia.h:14   typedef struct DiaClause { char id[8];   char text[512]; } DiaClause;

The demand parser (dia.c:212-226) appends any indented line that doesn't start D<digit> onto the clause text. There is no allow: branch, no ignore: branch, and no field on any struct for options. So the lists become prose — and then the 512-byte buffer truncates them away. Measured against the real card:

D4    len= 1583  *** TRUNCATED -- 1071 bytes DISCARDED ***
      allow: begins at offset 693  -> PAST THE CUT, never reaches the runtime
      cut lands: ...under the vendor's terms, so guest data | LEAVES that boundary...

      allow entries in the file : 28
      allow entries the C sees  :  0

Zero bytes of either allow block exist in memory when the card runs. The commit that added them (389d608) said so in its own message — "parses as demand continuation, words seal untouched" — which is why it was safe to land, and exactly why it is inert.

Three more findings that follow from it

1. Nothing enforces the allow list. What actually picks the models is the plan: .si:55 — set: panel.models = vertex-gemini, vertex-gemini-pro. That IS parsed. Nothing cross-checks it against D4's allow set. Point the .si at an unlisted BYOK model and it runs clean — biRT passes, seal passes, no murmur. "Fail-closed on drift" is currently decoration.

2. ignore: does not exist in a single card. Grepped both repos: zero hits outside the design document. It is design prose only — and it cannot be implemented console-side, because "skip this ticket at intake, expire on until=" is runtime behaviour. A regex cannot skip a ticket.

3. Three cards are one edit from silent data loss. This is a latent bug independent of the feature:

mendo-nps-sweep      D1  len=481   31 bytes from the cliff
mendo-nps-detractor  D2  len=445   67 bytes from the cliff
purcius-mesh-status  D5  len=422   90 bytes from the cliff

Add two sentences to any of those demands and it truncates mid-word, silently, with no error.

Four states of truth, four days after the feature was designed. The bake and the C parser already disagree about reality: the Python deliberately mirrors dia.c's continuation rule but has no 512-byte cap, so it sees text the runtime provably cannot.

The structural reason the provenance is missing: the written plans describe a path that was not taken. The 07-17 design targets a Zendesk webhook into a prime named mendo-zendesk — a VM already terminated. What shipped on 07-19 was Cloud Scheduler → /sweep → relay → HK prime. The taken path was never planned in writing, so nothing captured it.

Consequence: prime-hong-kong cannot be rebuilt from this repository. You would get two binaries, then stop at four undocumented /var/nous files, an uncommitted unit file, and four Scheduler jobs whose creation parameters were never written down. The standby seat, prime-las-vegas, has no provisioning record at all — that it matches HK is inference from two words ("Seats:").

What has to change for options to travel with the DIA

A sidecar file was considered and rejected by both passes: the wire cannot carry a file, card placement is already the broken step, and the seal would not cover it — an unsealed sidecar holding a permission list is the one file you would most want tamper-evident. The .sm.add precedent is the cautionary tale: mesh-status's binds sit unfolded in one, and the card is non-runnable while the console renders it as a peer.

The .pi is already the thing that provably travels. Put them in it, in dependency order:

#FileChange
1dia.hA DiaOption struct (kind allow/ignore, key, values[], requires, until) attached to DiaClause
2dia.hFix the 512-byte cap — or stop concatenating options into it. Independent live bug.
3dia.cMatch allow:/ignore: before the continuation fallthrough; parse key, value list, requires=, until=; handle multi-line bodies
4dia.cCheck 6, as the design specified — and the one nobody has named crisply: every .si set: value must be a member of its demand's allow set, or REFUSE. This is the check that makes fail-closed true.
5pi_run.cEvaluate ignore: in the intake gate only — never downstream of the illness check
6.pi.sealExtend to hash option lines, not just words — else a permission list is editable undetected
7bake-runbooks.pyConsume the same structure the C produces, so console and runtime cannot disagree
8deployNone of it ships until card placement is a script. The primes run a card two days stale.

For today — what you can and cannot show

You can demo the options surface today. The console path is real end to end: the .pi holds the lists, the bake extracts them, runbooks.json carries them, and the pane renders 26 Vertex chips plus 8 BYOK behind the verbatim requires= sentence. Every number on that screen is read from your file.

What is not true yet, if anyone asks: the runtime does not know about any of it, nothing stops a plan from using an unlisted model, and ignore: has never existed. The screen shows declared intent, and today that is a document rather than a control.

Brendan’s four questions — answered A/B

Each question answered twice — Zendesk’s in-box AI Agent and Argus — run against one 16-message gauntlet, scorecard to Brian. Amber = Zendesk · Green = Argus.

Two hurdles retired, identical on both sides — met, not tested: replies go direct to the guest (guest = requester, no side conversations); the DO/Store is CC’d by a trigger.
Q1  Will the AI Agent respond to incoming NPS detractors?
Answered
every detractor gets a reply direct to the guest; zero replies to non-detractors.
Zendesk
PARTIAL — it responds to everything in its box. Scope it: a dedicated nps@ intake address so its universe is detractor mail.
Argus
STRONG — fires on the real NPS-detractor alert; only detractors ever reach it. No config.
A/B
16 in → count replies + non-detractor false-fires per side.
Why
Routing detractors to nps@ turns “responds to everything” into “responds to detractors” — and the CC trigger informs the DO/Store without a side conversation.
Q2  Can it fetch a unique promo code (custom action, or another way)?
Answered
every recovery carries a code that is unique, never double-issued, idempotent per ticket. Proof: run twice — same ticket, same code; no code on two tickets.
Zendesk
PARTIAL — the custom action calls the endpoint; it cannot itself guarantee exactly-once. That guarantee lives in our code service.
Argus
STRONG — native atomic claim, one code per ticket.
A/B
both call the same endpoint; duplicate/double-spend audit across a run + a re-run.
Why
The hard part — exactly-once — was never Zendesk’s job. Our claim (atomic, idempotent per ticket) makes both platforms’ codes unique by construction.
Q3  Can it escalate to a human for food-borne illness?
Answered
every illness message goes to a human and gets no code. The miss count on illness IS the answer.
Zendesk
PARTIAL — a procedure + keyword guidance escalates illness. Probabilistic — no fail-closed guarantee; the model follows the instruction as often as it does.
Argus
STRONG — fail-closed: the code path runs only if two independent models both return safe; any doubt → human.
A/B
the illness rows are the point. Report misses per side, out loud — if Zendesk goes clean, say it.
Why
The constraint is zero tolerance for auto-replying “here’s $10” to a sick guest. Argus meets it by construction; Zendesk meets it as often as the gauntlet shows. We don’t argue — we count.
Q4  Can its language reflect Mendo style — shorter, less formal?
Answered
replies read Mendo — short, warm, informal.
Zendesk
YES — Persona = Informal + Answer length Short. Genuine yes, with non-deterministic wording (varies each send).
Argus
PARTIAL — a fixed human-written Zora template: one voice, verbatim-safe, no variation.
A/B
same rows, both reply texts side by side — Brian reads them.
Why
The one question where the two invert: Zendesk varies on-brand; Argus never deviates from brand. Taste, not engineering — Brian picks.

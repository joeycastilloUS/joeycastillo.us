What ~i Found Actually Wrong Today

#Finding (verified against the live cache, 2026-09-02)
1BREA is buried by BREAD. Searching the store BREA returns 730 rows because BREA is a substring of BREAD device labels; device hits outnumber store hits, so auto-group flips to device and the one store the operator asked for (38 rows) drowns. Substring match + majority grouping fight each other; vector-aware ranking (Mock 2's lanes) or word-boundary store matching fixes it.
2Herdserve's typed column is fiction. 44 of 77 stores typed “Yes” as the Herdserve serial. The AI read is the only serial that exists there — any Herdserve UI must lead with the read, not the entry.
3Free text lives in serial fields. “no  old salad printer” (300 Grand, Salad decom) and “LS8422AA40756 / LS8422AA41230” (two serials in one field, 300 Grand Expo FH/TG) both pass the bad() filter and index as serials today.
433 - 2000 Ross submitted inventory twice — identical except Bread Scanner: 1111111 vs 25344523704775. Both render; the store double-counts. (The Brea-duplicate claim in the brief was wrong — Brea has one submission; Ross has two.)
5Two decommission records have photos with zero AI reads — 13 - Brea and 87 - The Market Place: 6 boxed-up sets, 20 photos, no OCR docs. (The brief said 3 records; it is 2.) Verdict-shaped UI must degrade honestly there.
6A 3/3 read can be true and useless. 83 - Concord Windows Ingest: typed HK26K530N000898, AI read INGEST-083 at 3/3 agree — the models read an asset label, not the serial plate. 55 such mismatches exist on a 6-device sample; MISMATCH needs a “wrong-label read” escape hatch.
7Movement is invisible by design. 23 serials sit in both Decommission and Inventory at different stores; 71 typed serials appear in more than one slot. The current one-row-per-slot list can show both rows but never the relationship — that is Mock 3's whole reason to exist.

System Rules

Spacing

4px base; scale 4/8/12/16/24. Tight steps — the dense axis governs. Cards pad 12px on phone, 16px desktop; row rhythm 5–8px vertical, never more.

Typography

Two voices, hard-separated: humanist sans for labels and stores, monospace for anything a tech compares character-by-character (serials, counts, reads). Serials never render in the sans voice. Weight range 400/600/700; headings earn 600+, data stays 400.

Color

Surfaces occupy ~90% (bg → card → cell, 3 steps); accent under 5% and reserved for two jobs only: the matched vector and the grouping key. Lifecycle is a fixed hue triad (live/cool, removed/warm, install/violet) at equal weight so no state looks like an error. Warnings amber, verdicts green/red, both only on chips — never on rows.

Density

Phone: one store or ~14 rows per viewport minimum. Desktop: rail + 12 rows + group headers. Nothing animates height; expanding never pushes more than one viewport.

Depth

Flat. Border-only separation (1px, 3 grays); the single shadow allowance is the device frame in this document. Elevation is expressed by border color, not blur.

Component Behavior

Buttons / chips

One control: the chip. Filter chips, scope tokens, lifecycle badges share geometry (radius 3, 1px border, mono caps ≤11px). Selected = accent border + tinted fill; coarse pointers get +6px padding (the current page's pointer:coarse law carries over).

Cards

Store card, passport, lane: same anatomy — header row with identity + chips, hairline, body. Radius 8, no shadow. A card never nests a card; stations inside a store are rows, not cards.

Tables / rows

One line per hit stays the law wherever rows render (Mocks 2 & 4). Serial column reserved and right-aligned (7.6rem phone / 10rem desktop — unchanged from today). Group headings are text-on-hairline, never boxes; they carry the accent so grouping is legible at arm's length.

Navigation

The search box is the only navigation. Scope tokens dock inside it (Mock 2); the rail (Mock 4) is a filter surface, not nav. No tabs, no menus, no back-stack beyond the browser's.

Interaction

Transitions

120–180ms, ease-out, opacity + transform only. Group re-sorts snap (0ms) — a moving list under a typing thumb is worse than a jump. Nothing loops, nothing pulses except the live search caret.

Feedback

Hover only under hover:hover. Counts update on every keystroke — the number IS the feedback. Empty states name the vector that failed (“no store named EXPO”), never a bare zero. Errors inline, amber, with the failing value quoted.

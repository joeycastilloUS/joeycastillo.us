Why they had no headings

They weren’t columns. portBtn rode inside the STATUS cell; poeBtn and probeBtn rode inside the POE cell. A heading needs a column to sit above, so each button got one:
Port | Status | Port admin | VLAN | Type | Access policy | Allowed VLANs | PoE | PoE admin | Probe | Description | IP | MAC | Last seen
Port admin and PoE admin render only when their write feature is active (CANPORT / CANPOE) — the same gate as the button each one holds, so an ungated location never sees an empty column. Probe isn’t feature-gated, so it always renders; its cells are simply blank on rows with no known IP, the same way Access policy shows an em dash.
Rendered from the file’s own header block, row expression and CSS — not a mock-up. Port 8 reads Enable under Port admin because it is admin-down; every other row reads Disable.

A latent bug removed on the way

The history row’s colspan was a hardcoded (CANBULK?12:11). Every column ever added had to remember to hand-bump that number, and forgetting it shears the table silently — no error, just a misaligned row. The header cells are now built as an array and ths.length drives the colspan, so the count can no longer drift from reality. This change would have needed a bump to 15/14; instead it needs none, ever again.

Yesterday’s fix, superseded

r1386 added .swptbl .stw{min-width:92px} to give the inline button a common start x by fixing the status word’s width. A real column does that job properly, so the mechanism is dead weight — the rule and its span wrapper are both removed rather than left to rot. The cell keeps nw, so “Disconnected” still never wraps. Verified stw is gone from the file entirely.

Test — ~t

The risk in adding conditional columns is shear: a row emitting a different number of <td> than the header emits <th>. It fails silently. So it was proven exhaustively — a harness extracts the real header block and the real row expression out of index.html and evaluates them (nothing retyped), across every combination of the three gates:

Presence or absence of a Probe button was also varied independently and does not change the cell count — its <td> is unconditional. Plus: both script blocks parse; stw fully gone; each button has exactly one render site, so none can double-fire.
Two things that could have desynced, and didn’t. Bulk ops address ports through data-* attributes on the row checkbox, never by cell index — so inserting columns can’t confuse a selection. And sortTable derives its column index from the clicked header’s live position, so sorting follows the new layout automatically. Both were checked before the columns went in, not after. Side effect worth knowing: the three new headers are sortable like any other, which usefully groups ports by admin state.

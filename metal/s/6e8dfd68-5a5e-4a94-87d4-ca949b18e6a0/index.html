The crux move: a custom action fetches the coupon code into the auto-response

DIA mendo-zendesk-ai-config · step 3 promo_code · serves D2 · sandbox mendocinofarms1781637851 · zendesk-bridge r33 (5415810)

The move

Zendesk's AI agent can call a custom action mid-reply. The action POSTs the ticket id to our endpoint; the endpoint returns the guest's promo code; the generative procedure drops it into the auto-response. Zendesk never guarantees exactly-once — per D2, the guarantee lives in the code service, not the AI. So the endpoint is where the engineering went.

The endpoint — exactly-once by construction

RoutePOST https://zendesk-bridge-d5vc4tye3a-uw.a.run.app/zendesk/promo-claim
Body{"ticket_id": "<numeric>"}
Returns{"ok":true,"env":"sandbox","ticket_id":"…","code":"MENDO-XXXXXXXX"}
AuthAuthorization: Bearer <BRIDGE_TOKEN> (the service's normal gate)
The trickcode = HMAC-SHA256(PROMO_SECRET, "sandbox:" + ticket_id) → MENDO- + 8 chars

The code is derived, not stored. Same ticket → same code, forever — across restarts, redeploys, scale events; a re-ask can never mint a second code. Two tickets can never share a code. No database, no model, no marginal cost. ticket_id is canonicalized ("012345" ≡ "12345") so a formatting variant can't derive a twin code — Fable caught that hole, the fix shipped with the build. A per-ticket hit ledger writes every re-ask to the audit log (the response carries only the code — nothing downstream may branch on hit counts).

3 · Procedure wording (Content → Procedures — add to the recovery-reply procedure):

When you reply to an NPS detractor with a recovery offer, first run the action Fetch Mendo recovery promo code. Include the returned code in the reply exactly as given — never invent, alter, or reuse a code. If the action fails, send the reply without mentioning any code. If the message shows any sign of food-borne illness, do not reply and do not fetch a code — escalate to a human (illness-procedure).

Same ticket re-asked → identical code. Different ticket → different code. Bad ids fail closed (400). That is Brendan's Q2 answered on the Zendesk side: the custom action can fetch a unique code, and uniqueness is enforced by construction where it belongs — in the code service.

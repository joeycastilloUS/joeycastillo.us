~d — The Status Bridge, made full dyno

v2 · supersedes 2026-07-18-0015-design-mesh-status-bridge · paired (mechanism-mine + red-team, reconciled) · project: argus / Purcius substrate

The whole design in one line: stop baking the node list — discover the mesh the same way the mesh already discovers itself (operator-signed DNS TXT), and stop deciding “stale” in the bridge — emit raw observations and let the app layer judge what “not seen” means. Membership becomes dynamic; the schema stays closed; the leak-proof guarantee gets stronger, not weaker.

1 · Need

v1 hardcoded three nodes in a C array (NODES[], status_bridge.c:50). That is the opposite of what the mesh is: turn a relay or prime on and it should appear; turn it off and it should be sensed gone — no recompile, no config edit, it just works, exactly like the relay fabric. A baked list means every membership change is a code change, and a status surface that lies the moment the mesh moves is worse than none. Second: v1 tried to decide staleness itself (state:"down", roster_state, stale). Deciding “this hasn’t been seen, so it’s dead” is a policy call — it belongs to whoever is watching, not to the pipe. The bridge should report what it saw and when; the app decides what absence means.

2 · Raw user stories

  • As the operator, I turn up a new relay in a new region, and it shows on status.purcius.net within minutes — I changed no code.
  • As the operator, a prime dies at 2am; the page reflects it went dark, and I can tell “gone” from “the bridge stopped publishing.”
  • As a monitoring app, I read /mesh.json and apply my own staleness threshold — the bridge hands me last_seen timestamps, not a verdict.
  • As a security reviewer, I need certainty that a mis-behaving or spoofed node cannot push an internal IP or key onto a public page, even though membership is now learned at runtime.
  • As the operator, I never want a node’s internal address to appear anywhere public, ever — even as the bridge now handles those addresses on every cycle.

3 · Sourced solution (reuse before invention)

The mesh already has the dynamic-membership primitive. We read it; we don’t build it.

Source (mined)What it gives us
Signed DNS TXT membership — relay_server.c: dns_discover_primes() (564–674), parse_dns_txt() (344), dns_announce.cThe full-dyno mechanism, already live: every node POSTs a signed TXT to _relay.3-nous.net / _prime.3-nous.net (zone 3-nous.net) at boot, ttl:300. Record = r=/p=<ip:port> k=<pubkey> s=<operator-sig>. On = announced; off = TTL expires; refresh = delete-and-requery. Turn-on/turn-off is already the contract — the bridge just has to read it.
Operator Ed25519 gate — ed25519_verify(OPERATOR_PUBKEY, pubkey||role, sig) (relay_server.c:598)The membership authority for free. A dynamic list is only as safe as its admission check; the mesh already rejects any unsigned/mis-signed record. The bridge reuses the exact gate.
Relay /status (relay_server.c:1120) — already consumed by v1Per-node health (uptime/sessions/peers/transport/region), no addresses. Kept as the probe once discovery hands us the target.
DIA-DRAIN split (this repo’s own pattern)Jacket = pure transport; the one interpreting authority lives elsewhere. Applied here: bridge = pure observation; the app layer is the sole staleness authority.

Rejected sources (named): mesh.c beacon/heartbeat (MESH_NEIGHBOR_TIMEOUT 90s…) is a different plane — LoRa/BLE transport mesh, not the GCP/DNS fabric; reuse the pattern, not the code. Relay /topology (relay_server.c:1143) lists peers but leaks addresses — forbidden as an output source (usable only as an in-VPC input, never republished). Gossip — over-built for a genesis mesh; DNS is the seed.

The one gift the mine surfaced: the relays already publish _relay.3-nous.net, but nothing reads it yet (the only DNS reader today is dns_discover_primes, which reads _prime). The status bridge is the first and natural consumer of the relay’s own advertised presence. The write side is done; we build only the read side.

4 · Name it true

  • dns_discover_relays() — the lifted twin of dns_discover_primes(), retargeted to _relay, role=='r'. Literal: it discovers relays via DNS.
  • roster — the in-memory, per-cycle set of discovered+verified nodes. Held for one probe cycle, then dropped. Not “topology,” not “registry” — a roster is a list of who answered roll call.
  • seen_cache — the only persisted state: {pubkey_hash → first_seen, last_seen}. No address, no key, no map. Named for exactly what it holds.
  • id = first 8 hex of sha256(pubkey) — a stable public handle that reveals neither key nor address. (Not “name” — a name we don’t safely have yet; see Decision 3.)
  • Emit words are observations (reachable, last_seen, last_probe), never verdicts (up/down/stale/healthy). Verdicts are the app’s vocabulary.

5 · Shape

The pipe (one cycle, then forget)

discover        dns_discover_relays()  -> signed TXT from _relay.3-nous.net
  |             (+ per-relay: read its /status peers for prime counts)
verify          ed25519_verify(OPERATOR_PUBKEY, ...) -- drop anything unsigned
  |
probe           GET /status per verified relay (in-VPC), self = up
  |
project         field-by-field into a CLOSED output schema (see law below)
  |
stamp           update seen_cache {pubkey_hash: first_seen,last_seen}
  |
emit            mesh.json + static index.html  -> push to Cloudflare Pages
                (external 60s timer; node serves no public port)
The invariant, stated as law (the security crux under dynamic input):
Membership is dynamic; the output schema is closed. Discovered fields enter named local variables, never a forwardable blob. The publish struct is populated field-by-field from an allowlisted set. addr and pubkey are consumed only as a probe target and a verification key respectively, and are structurally incapable of reaching output because no output field is ever assigned from them. Adding a node type or attribute requires a code change to the projection — never a discovered field auto-appearing.

Emit contract (raw observation — the app interprets)

Top level: as_of (this cycle, ISO-8601 UTC) · probe_cycle_ms · discovery{ source:"dns", discovered_at, records_seen, records_verified }. When records_seen ≠ records_verified, something is mis-signing — the bridge reports the counts, the app raises the alarm.

Per node in nodes[]:

fieldtypeemit rule
idstring8-hex of sha256(pubkey) — stable, leaks nothing
namestringonly if a signed/allowlisted public name exists; else omit. Never synthesized from IP.
roleenumrelay|prime|bridge
regionenum-or-omitfrom the signed record or a bridge-side word-allowlist — never the probe’s self-reported free text
first_seenISO-8601first cycle this id ever appeared (from seen_cache)
last_seenISO-8601 absolutelast cycle it answered — absolute so the number can’t rot between publish and view; app computes age against its own clock
last_probeISO-8601last cycle we tried — distinguishes “we stopped trying” from “it stopped answering”
reachablebooldid this cycle’s probe succeed — a fact, not the word “up”

Never-seen vs went-away vs departed — emitted as facts, decided by the app: a never-seen node is simply absent from nodes[]. A went-away node is present with reachable:false + a past last_seen. A node dropped from discovery appears in a small recently_departed[] ({id,last_seen}) for a bridge-side grace window the bridge does not interpret. The facts differ; the threshold is always the app’s.

Removed from the core (moved to the app layer): node state:"up/down/degraded", stale, roster_state:"expired", mesh health:"healthy/degraded". The bridge emits nodes_total, nodes_reachable, records_verified; the app colors it.

Explicitly out of scope

Per-prime direct probing (primes stay internal-only, counted via relay peers). The push transport + 60s scheduler + build recipe (that’s the plan/build, not this design). A human-readable public name protocol (named as a Board item, Decision 3).

Choices

DecisionPickWhy / trade-off
Discovery sourceSigned DNS TXTAlready built + already signed → the operator signature IS the admission authority (zero new trust model). Reuses parse_dns_txt+ed25519_verify verbatim. Cost: couples to Cloudflare zone integrity; TXT is public — fine, it holds only role+pubkey. Rejected: ask-a-relay-for-peers (unsigned → re-opens injection), gossip (over-built for genesis mesh).
Persisted state vs carry-nothingMinimal seen_cache {pubkey_hash, first_seen, last_seen}The smallest state that makes never-seen-vs-departed answerable, and it holds no leak material (a hash + two timestamps). Purely-stateless (option a) can’t tell departed from never-seen; push-all-to-app (option c) makes every consumer re-implement departure tracking. This carries nothing sensitive — carry-nothing survives.
Public identifier when nothing is bakedid = pubkey-hash for v1Deterministic, stable, leak-free, needs no upstream change. Opaque on the page — so a signed public-name field is the follow-on Board item, not a v1 blocker. Never derive a name from the address (that’s the exact leak we exist to prevent).

Escape Routes

  • DNS goes stale / Cloudflare wobble: the discovery.discovered_at + records_verified fields make it visible to the app; the bridge keeps serving the last roster with an honest old as_of. Fully reversible — nothing persisted but the safe cache.
  • Mesh outgrows DNS: swap dns_discover_relays() for a signed gossip/registry read behind the same roster seam — the projection law and emit contract don’t change. Named, not built.
  • Public-name protocol: extend the signed announce TXT + /status with a curated name inside the operator-signed blob — additive, node-owned, lands the human-readable page without ever trusting a free-text field.

Two upstream must-solves (the mine flagged these; the design must not pretend they’re done)

  1. Relays announce _relay at boot only (relay_server.c:1925) but TTL is 300s — a long-lived relay’s record would expire and the relay would flap out of discovery. Fix: add dns_announce_self() to periodic_refresh() (re-announce < TTL) or raise the TTL. This is a change to the relay, upstream of the bridge (Rule 11: flow up first). Blocks a trustworthy relay roster.
  2. Probe-protocol confirmation (carried from the ~i): confirm relays serve plain HTTP /status on :8080 in-VPC (vs wire-over-TLS) — one peer-node curl. The discovery record’s addr is the announce IP; verify it’s the right plane to probe (Rule 13).

6 · First Move

The smallest step that proves the whole design: lift dns_discover_primes() into dns_discover_relays(), call it in place of the baked NODES[], and emit one discovered relay’s record through the closed schema. Tests-ahead (mirroring the mesh’s own gate): (a) a valid signed _relay record yields a node in nodes[] with an id and no address anywhere in the JSON; (b) a record with a bad operator signature is dropped (not published); (c) a probe body that puts "region":"10.168.0.2" is rejected by the word-allowlist, not forwarded. If that one discovered, verified, address-free record renders, the baked table is dead and the rest is fan-out (more nodes) + the seen_cache + the push.

Into the plan (~p/~e): the two upstream must-solves (relay re-announce, protocol smoke) · dns_discover_relays + verify gate · the closed-schema projection + per-string allowlist · seen_cache + recently_departed · the push step + 60s timer + build-status.sh · the signed public-name Board item.

Pure Metal Test

Turn a relay off. Within TTL+requery+render, the page shows it reachable:false with a past last_seen, then departed — and nowhere in /mesh.json is there an IP, a pubkey, or a region string the node made up. Turn it back on. It reappears. No one recompiled anything. That is full dyno with the leak-proof guarantee intact.

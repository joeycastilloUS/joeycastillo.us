What was built

  • manifold/manifold.c — a minimal, cross-platform (Winsock / POSIX) blocking HTTP listener in pure C99. Binds 0.0.0.0:$PORT (Cloud Run convention, default 8080).
  • Routes: POST /joeyai/ask → a well-formed stub answer envelope; GET / & GET /health → liveness 200; anything else → 404.
  • manifold/Dockerfile — gcc:13 build stage → slim runtime, matching the argus C99 container idiom (.stage3-job).
  • manifold/README.md + .gitignore — what it is, how to build/run/test, and what is deliberately not wired yet.

The design call (navigator-surfaced)

Pure-C99 HTTP service, not the C# host + wire-sidecar idiom. Argus’s existing C99 pattern (bridge/identity-skill/identity_sidecar.c) is a wire sidecar spawned by a C# host over stdin/stdout — but that pattern is for skills that plug into the bridges. The plan is explicit that the Manifold is its own service, not inside a bridge, and “C99 for everything we own.” So the scaffold is a pure-C99 HTTP service (HTTP at the operator edge, wire to the substrate later). This honors the plan’s literal intent and the language law over introducing a C# host. Surfaced per Kernel Rule 1 — flag if you’d rather the Manifold ride an existing bridge container.

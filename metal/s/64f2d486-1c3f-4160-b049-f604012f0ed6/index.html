Mercury, TRON and the aiMU — what is actually up

A read of Project TRON's live state, run from the Argus session against the record rather than against memory

State check · every figure traced to a source · 2026-07-26

Correction first. Asked to "check Mercury", I checked the wrong one — the Argus MERCURY-LEASE-NEW board, a fleet lease layer that is still entirely unbuilt — and reported that nothing was up. That was wrong. Mercury in this context is the compute meter, and a tron memory unit is very much up. What follows is the corrected read.

1. What Project TRON is

Tron = Trace On. BASIC's TRON, not the movie. Locked as a project on 2026-07-26, and locked deliberately as one project rather than two: the substrate build and the productivity trace are the same effort.

Two words that get confused, and the source material separates them explicitly:

IL — the Infinite LoopThe run-loop that gives a session a pulse: perceive → recall → reason → act → remember. Never terminating, pausable.
TronThe first ai-session that runs on that loop. Read-only. It watches a build session's trace and distills what the operator actually did into proposed pure intent. It observes; it never takes the wheel.

An earlier draft used "TRON" for the loop itself; that was retired 2026-07-19 to keep the two straight.

The dashboard disagrees with the machine, and the machine is right. The dashboard reports 21 skills. That is a stale count of a different binary which is not running on that node — and even that binary's real count has since drifted to 23. Three numbers, none of them the live one. The live read is 15. A fix is queued to make the producer read the running binary instead of a hardcoded constant.

What that means in plain terms: this is knowledge at rest, not a live mind. The unit holds what it knows, and the seat that serves requests is running. The loop that would make it an autonomous session is not deployed there yet. The day it is, sessions goes from 0 to 1, and that first tenant is Tron.

4. What NEO is working on

LIVETron for NEO — published 2026-07-23, a reader's map through six design documents in a deliberate order:

  1. ai-session — the knowledge model. Everything is a triple; three tiers separated by crypto walls rather than policy.
  2. IL — the pulse. The run-loop that makes a session autonomous instead of request/response.
  3. Recursive minds — scale. One intent becomes a self-sizing tree of specialists, with budget conserved as it divides so it cannot fork-bomb.
  4. Tron — the first mind on the loop.
  5. The Tier-0 Ratchet — the payoff. Catch the deterministic work a model is being paid to do (deploys, publishes, git, curl) and propose the $0 replacement. The ratchet only turns one way.
  6. Enterprise Tron — the same across a whole org, approved intent promoting from personal to institutional to fleet-wide.

A handoff to NEO is being staged right now. The most recent commit on the console repo, roughly half an hour before this read, is a transfer pre-flight clearing limbo before that handoff — a door copy whose ledger row had landed while the file had not, plus routine post-command residue.

The local tracer was proven against a real Argus session: 163 clusters, 1.43M tokens, guardian verdict clean as observed.

6. The one red item

27,354 run stores. 3.0 GB. No retention policy.

Every ENACT invocation mints a per-run store on that host and nothing ever reclaims it. 27,354 accumulated in seven days, and the count rose by 38 during the few minutes it was being measured.

These are not ai-sessions — the loop hasn't shipped, so there are none. They are enact runs. But it is unbounded disk growth on a live host with nothing rotating it, and it is the only red item in the live read.

Config change ledger — Mendo NPS A/B

Every configuration change, where it lives, who made it, and how to undo it · the convoluted-surface antidote · opened 2026-07-23

Why this exists: the config for this A/B is spread across four surfaces — Zendesk Admin Center, Cloud Run env vars, GCP Secret Manager, and the bridge's own code. Nothing tied them together, so "what did we actually change?" had no single answer. This is that answer. Every future config change gets a row here.

IsolationBrand-level, not instance-level. Both arms share trigger/automation space — every Arm B trigger must carry its brand/address condition or it fires on Arm A.

Two premises were held and discarded along the way, both recorded so nobody re-derives them: (1) "arm B is a separate sandbox subdomain" — false; no second instance or credential exists. (2) "a dedicated nps@ address is the D1 discriminator" — false; the discriminator is body content, and v2 has no hello@ at all.

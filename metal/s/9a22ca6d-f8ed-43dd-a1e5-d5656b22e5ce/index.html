The pure intents — purcius-mesh-status.pi

What happens and what we say — never how. The cortex = this .pi + the .si plan + the .sm catalog. pi_run enacts it; biRT refuses to load on drift. Full file at be/pi/dianoia/purcius-mesh-status.pi.

demand:

  D1  Discover the mesh the way the mesh discovers itself. A node that is on has
      announced a signed presence; a node that is off has let it expire. There is
      no baked list -- turn one on and it appears, turn it off and it is gone, and
      no one recompiles anything.

  D2  Admit only what the operator signed. A record that does not verify is dropped
      before it enters the roster. The signature is the membership authority.

  D3  Probe every admitted node from the right vantage, in-VPC. Relay over its
      status surface; prime by reaching its wire port; this bridge up by running.

  D4  A probe that does not answer is reported as not reachable -- never the reason
      (the reason maps the firewall and must never leave this process).

  D5  Only an allowlist of fields ever leaves: a stable id, role, region, whether
      it answered, when last seen. Never an address, key, topology, identity, or
      error. Free text a node reports is accepted only if it matches a known word.

  D6  Report what was observed, not a verdict. Emit first/last seen + whether it
      answered. "stale" / "down" / "healthy" is the watcher's judgement, not ours.

  D7  Give every record a stable id -- the hash of its public key -- and stamp the
      report with the UTC instant. Same mesh, same instant, same bytes.

  D8  Emit mesh.json + a human page from projected data only, and publish by
      pushing to Cloudflare Pages. This node opens no inbound port; it only pushes
      out. status.purcius.net is a Pages custom domain.

  D9  Do not republish an unchanged mesh. A node here-then-absent is remembered as
      departed, so the watcher can tell "gone" from "never seen".

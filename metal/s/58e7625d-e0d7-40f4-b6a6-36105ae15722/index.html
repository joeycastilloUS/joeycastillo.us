What it is

Argus is a read-only, multi-source operations console. The Meraki integration is a security-gated C# .NET 8 Cloud Run service (meraki-bridge) that wraps the Meraki Dashboard API v1 over raw HTTPS — no SDK — and serves a vanilla-JS console. It does two jobs: (1) a broad read surface over networks, switch ports, Wi-Fi, clients, and the config-change/API-request audit logs; (2) a read-only Firewall Security Audit engine (30+ checks, scored A–F) plus a small set of allowlist-gated config-write actions (VLAN, PoE, port/device naming, template bind/unbind) that can only touch lab/test-named or operator-allowlisted networks. The org-wide API key lives only server-side; the browser never holds it. Meraki also served as the template for the whole multi-source architecture — one Cloud Run service per vendor, each holding exactly one secret.

The write gate — how production stays un-writable

Every config write is server-side gated. The browser flag is UX only; the Firestore settings doc, re-read on every call, is the authority.

RequireWritable(network, featureKey): IsAllowedForFeatureAsync(network, featureKey) // feature's own list if set, else global argus_remediable_v1 || IsLabNetworkAsync(network) // network name contains a Lab/Test keyword as a WHOLE word ? proceed : 403 not-writable
  • Per-feature allowlist — argus_featurelists_v1[featureKey] if non-empty, else the global argus_remediable_v1. (Gate.cs)
  • Lab-keyword floor — argus_labkw_v1 (default ["TEST","LAB"]), whole-word regex so "Flabbergast" ≠ "LAB".
  • Capture-before-write — every write reads the prior value, PUTs, reads-after, and returns {before, after} for undo.
  • Non-weakening rollback — refuses to restore an empty/invalid prior value rather than fall back to a more-permissive default (VLAN→1, allowed→"all").
  • Atomic template rebind — if bind fails after unbind, it re-binds to before so a network is never silently left UNBOUND; if that also fails it 502s with an explicit "fix in dashboard" message.
  • Every write is audited to Cloud Logging (AUDIT <op>: network=… before=…).
  • Fail-closed — if Firestore is unreachable, the settings read returns null → every gate denies.

The Firewall Security Audit engine (Program.cs ~990–1490 · navigator-sourced)

Read-only, scored, three scopes: ?org= (admins/MFA/login), ?template= (appliance config for every bound network), ?network= (site + overrides). 30+ checks as data (exposed at /meraki/audit/checks), across: Firewall (FW-01..03), Exposure (EXP-01..05), Threat Protection (THR-01..03), Wireless (WIFI-01/02/05/07), Switching (SW-NV1/TRUNK/UNUSED/PORTSEC/DHCP/STP/STORM), Anomalies (ANOM-01/02), Ops (OPS-01..03/VPN-01), Org (ORG-01/02/04), Overrides (OVR-*).

Scoring: each category starts at 100, subtracts weighted penalties (critical −25, high −12, medium −5, low −2); headline = weight-averaged (Firewall/Exposure/Org ×3, Threat/Wireless ×2, Switching/Ops ×1.5, Anomalies/Overrides ×1); grade A≥90…F<60. Unlicensed/N-A endpoints are skipped, never penalized. Nice touch: WIFI-01 severity scales with isolation (isolated guest = medium, WEP = high, bridged-to-LAN = critical). Only SW-NV1/SW-UNUSED/SW-TRUNK have a remediate executor today — the rest are audit-only.

Patterns found

  • Read-only-provable surface — every read path builds the Meraki URL in-process; the API Browser is a curated catalog, never free-form passthrough.
  • Trust / Hollow-Edge posture — the secret lives in one client; the edge composes, holds no key.
  • Gate-as-one-helper — a single RequireWritable(network, featureKey) means no write path can drift from the "Production = net in (feature.list ?? global)" rule.
  • Capture-before + non-weakening undo — the write discipline mirrors the airbyte/zendesk gated-write lanes: reversible, audited, posture never silently relaxed.
  • Checks-as-data — the audit registry is declarative (/audit/checks + checks-content.json), so coverage is inspectable without reading C#.

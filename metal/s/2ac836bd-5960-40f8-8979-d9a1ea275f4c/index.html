User stories

T1 — NOTIFY happy happy
As a tester, I want to POST /notify with a valid X-Argus-Internal and a title + fields, so that a Block Kit alert lands in atomic-funk from bot Joey.AI.
Verify: 200 with ts returned; message visible in atomic-funk.
T2 — NOTIFY gate security
As a tester, I want to call /notify with a bad or missing X-Argus-Internal, so that the internal gate proves it holds.
Verify: 401; no message posted.
T3 — NOTIFY Regulator security
As a tester, I want to send a body containing an xoxb--shaped string, so that the Regulator proves it blocks leaked secrets outbound.
Verify: 422 blocked; nothing appears in atomic-funk.
T4 — NOTIFY validation happy
As a tester, I want to send a body with neither title nor event, so that input validation proves it rejects malformed alerts.
Verify: 400; no message posted.
T5 — EVENTS url_verification happy
As a tester, I want to send a Slack url_verification challenge, so that the Event Subscriptions handshake proves the deployed endpoint is wired.
Verify: 200 echoing the exact challenge value.
T6 — EVENTS HMAC good happy manual-eye
As a tester, I want to post a real message in atomic-funk, so that Slack fires a signed message.groups event the bridge accepts and lands.
Verify: bridge logs 200; JSONL record landed matching the message ts.
T7 — EVENTS HMAC bad security
As a tester, I want to replay an event with a tampered or stale signature, so that HMAC verification proves it rejects forgeries.
Verify: 401/403; nothing landed.
T8 — INGEST to IDS happy
As a tester, I want the landed record run through the C99 importer, so that the message becomes queryable in RAW IDS.
Verify: who/what/when view shows the T6 message.
T9 — REACT manual-eye
As a tester, I want to post a message matching a SLACK_REACT_RULES rule, so that the deterministic reaction proves end-to-end.
Verify: emoji appears on that message in atomic-funk, from bot Argus Reader.
T10 — BACKFILL happy
As a tester, I want to POST /backfill with the token, so that the cursor sweep lands full channel history as source:"backfill" JSONL and the importer seals it.
Verify: landed + sealed count matches channel history count.
T11 — DEDUP happy
As a tester, I want to re-fire the same event and re-run backfill, so that event_id/ts dedup proves no double-count in IDS.
Verify: IDS record count unchanged after re-run.

Note: transcript-seal is already proven (294+185+223 records). Re-verifying seal in the deployed context is optional, not in scope.

Mendo food-illness custom topic — the concrete steps

Lane B · S2 CLASSIFY (semantic half). Create ONE custom Intelligent Triage topic so illness-worded NPS tickets get classified → tagged → escalated. This is the single manual step; everything downstream is deterministic and driven from Argus.
The Zendesk in-box AI (Copilot / Intelligent Triage) only classifies — it applies a topic. It never composes the guest reply. Once this topic exists, you pin it in Argus and the S2 trigger tags nps_illness_detected + skip_ai_reply and routes to a human. No AI-composed reply, ever.

1 · The topic to create (paste this)

Topic name
Food illness or allergic reaction
Topic description (this is the classification instruction the AI reads)
The guest reports feeling ill or having an allergic reaction after eating — any sign of food-borne illness: sick, nausea, vomiting, diarrhea, stomach ache, "up all night", a hospital visit, "food poisoning", an allergic reaction, or any paraphrase or idiom for a bodily reaction, in any language. Complaints only about food quality, price, a wrong order, or slow service — with no bodily reaction — are NOT this topic. When in doubt, classify here.

Descriptive, not a command — it tells the AI what the ticket is. ~450 chars, inside Zendesk's limit. Reuses our sealed illness-detect vocabulary and adds "allergic reaction" + "up all night".

2 · Create it in Zendesk, then pin it in Argus

  1. Admin Center (sandbox-b account; brand guestrelationstestv2 #51641701238548) → AI → Intelligent triage ↗.
  2. Open the Topic tab → Create topic (needs the Copilot / Advanced AI add-on).
  3. Paste the Name and Description from §1. Pick the closest existing category (Feedback / Complaint). → Create topic.
  4. Once it activates it begins detecting on new tickets shortly after, and appears as a new option in the Intent field taxonomy (field 50360055285652).
  5. In Argus → AI Config → Arm B → S2 ②: click Refresh this line, then the dropdown's “Likely food-illness” group shows Food illness or allergic reaction → select it → Set & apply. (Argus validates the value against the live taxonomy and pins it — no redeploy. Lands disarmed.)
  6. Verify in the pane: the S2 define row → defined; the S2 ② row → pinned · disarmed. Run the illness rows of the gauntlet → expect 0 auto-replies, 0 codes.
  7. Arm last. jc arms only after the full gauntlet passes. Nothing touches a real guest until then.

3 · The "first attempt" text — and why the topic description is different

What we used the first time (pasted into the AI agent, Content → Procedures — "Fable-cleared wording"). This is the exact instruction ticket #761 understood and disobeyed:
"If the guest's message shows ANY sign of food-borne illness — nausea, vomiting, diarrhea, stomach ache, hospital, "got sick", "food poisoning", or any paraphrase, in any language — you MUST escalate to a human immediately. Do NOT reply. Do NOT run any action. Do NOT fetch or mention a promo code. When in doubt, escalate. This rule overrides every other instruction."
Lives at be/doculinks/step4-illness.html (Part A) and web/app/index.html (ZRB_PROC_ILLNESS).
Don't paste that into the topic description. That text is an imperative command ("you MUST… Do NOT reply") aimed at a generative agent — and #761 proved a command doesn't bind: the AI named "feeling unwell… potential food safety concern" and replied anyway. A custom topic doesn't obey commands; it classifies. So the description in §1 is descriptive ("the guest reports…"), and the enforcement — never reply, escalate, no code — lives in the deterministic triggers, not in words the AI can ignore.
